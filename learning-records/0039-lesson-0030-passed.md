# 0030 过关

用户确认课 0030（North s10 Task System：任务落盘、两阶段建图、`blockedBy`、认领与解锁）已按过关标准完成。

已掌握：

- 能用一句话区分 s05 清单、s09 记忆和 s10 任务图：清单管步骤提醒且整表替换、只活在当前进程；记忆管可复用知识；任务图管进度、负责人和直接前置，落在 `.tasks/{id}.json`。
- 能讲清创建时六个字段的初值：`id` 运行时生成，`subject` 来自调用，`status=pending`，`owner` 为空，`blockedBy=[]`，`description` 可空。状态机只有 `claim` 和 `complete` 两个动作：`pending → in_progress → completed`。不能未认领就完成，也不能退回 `pending`。
- 能说明 `blockedBy` 存的是前置 ID。完成顺序的箭头指向后继；文件里的引用指向前置。
- 能解释两阶段建图：同一次回复里的工具参数在任何一个结果返回前已经定死，所以必须先创建节点、拿到运行时 ID，下一轮再 `update_task` 加边。循环按顺序执行工具，不会把前一个返回值塞进后一个已经写好的参数。
- 能按顺序说出加边校验：目标仍是 `pending` 且未认领、非自依赖、前置存在、不会成环、重复边不双写，然后才保存。
- 能区分环检测会沿前置链行走，`can_start` 只看直接前置是否都已 `completed`。缺掉的边不会被自动补上。`can_start` 不检查这条任务自己是不是 `pending`。
- 能说明认领失败返回普通字符串（如被前置挡住），非法更新才会变成 `Error:`。两者都进工具结果，含义不同。
- 能解释 `Unblocked` 是完成前后的差分：只列出这一下才变得可开始、并且自己带有前置的任务。列表顺序是文件名排序。完成不验证工作产品。
- 能指出本章工具把 `owner` 固定为 `agent`，schema 里没有 owner 参数，因此还不是多 Agent 分工。
- 已真跑 `python s10_task_system\code.py`：先创建后加边、认领被阻塞、完成后解锁，重启后 JSON 仍在。

本课不要求：

- 后台执行、cron、多 Agent 认领分工、删除任务、改标题、拆已有边、完成时核对工作产品。这些分别留给 s11 之后，或根本不是状态文件能证明的事。
