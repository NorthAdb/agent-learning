# 0029 过关

用户确认课 0029（North s09 Memory：跨会话记忆的存储、召回、提取、筛选与整理）已按过关标准完成。

已掌握：

- 能区分 s08 Context Compact 与 s09 Memory：前者管理当前 `messages` 的上下文预算，后者筛选值得跨会话复用的知识。
- 能解释一条记忆的存储结构：`.memory/*.md` 保存完整记录，YAML frontmatter 保存 `name` / `description` / `type`，`MEMORY.md` 是由记录文件重建的短索引。
- 能说明 `memory_slug()` 的中文语境：把自然语言名称转换成适合文件名、URL 或稳定键名的机器友好标识；`name` 给人看，slug 给程序用。
- 能区分 `_memory_slug()` 与 `memory_slug()`：前者目前只是内部包装函数；单个 `_` 是“内部实现约定”，不是 Java `private`，不会真正阻止外部访问。
- 能解释 `_normalized_memory_text()`：统一小写、折叠空白，用于重复比较；它不修改写盘正文，也不是翻译器或语义相似度算法。
- 能完整讲出召回顺序：目录 `name + description` → 轻量模型返回相关编号 → 校验编号、去重、最多 5 条 → 按返回顺序读取正文 → 总量最多 20000 字符。
- 能区分“最多读取五条”与“固定读取前五条”：模型返回什么编号就按什么顺序读取，关键词降级时则按命中分数排序。
- 能解释关键词降级：模型调用或 JSON 解析失败时，退回按请求关键词匹配记忆目录；模型正常返回 `[]` 表示无相关记忆，不属于异常。
- 能指出当前教学实现没有自动评估“召回记忆是否真的有用”：它记录了选择和加载，但没有验证哪条记忆实际影响了回答。
- 能说明适合写入记忆的内容：长期用户偏好、以后仍适用的反馈、稳定项目事实和用户希望保留的外部参考。
- 能说明不应写入的内容：临时任务状态、工具输出、助手猜测、当前对话总结，以及 `current_task` 范围的本轮限制。
- 能按写入前检查顺序说明 `should_store_memory()`：`scope=persistent`、合法 type、字段非空、过滤临时标记、过滤重复内容。
- 能解释整理的快照恢复：达到 10 条后先校验整理结果并保存旧文件快照，替换失败时删除半成品、恢复快照并重建索引；快照保证可恢复，不保证模型整理后的事实正确。
- 已观察到 North s09 生成 `.memory/MEMORY.md` 与 `tab-indentation-preference.md`，能把磁盘上的持久记录与当前模型是否实际使用它区分开。

本课不要求：

- 向量数据库、embedding、语义相似度评测、记忆自动过期、生产级加密、多租户隔离和并发写入控制。
- 为召回增加使用日志、来源引用或自动效果评估；当前 North 教学实现只负责选择和注入，不验证记忆是否改变了回答。
