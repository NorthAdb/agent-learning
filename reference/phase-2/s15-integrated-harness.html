s15：Integrated Harness

不新增机制。规定每种旧事件在同一轮的哪一步写进同一份 messages。

来源： s15 README L59–177； code.py L3102–3261。

一轮

注入 cron 与后台通知
  ↓
prepare_context
  ↓
组装 system 与工具池（26 个内置名 + 已连接 MCP）
  ↓
call_llm 成功才确认 cron
  ↓
无 tool_use → Stop、记记忆、释放 assignment
有 tool_use → PreToolUse → 后台占位或同步执行

和单章不同的缝

  • task 是一次子代理。create_task 才写任务图。todo_write 是会话清单。
  • 后台：主线程不对占位结果跑 PostToolUse；worker 里对着真实输出再跑。
  • 非主线程：所有 bash 直接拒绝。需要确认的 MCP 也直接拒绝。
  • async_event_loop 在你不打字时，因 cron、Lead 收件箱或后台结果再开一轮。
  • 先注入再压缩。通知不是永不裁剪的侧频道。

没改义的部分

  • 后台仍要 bash 且布尔真。cron 仍是五段。MCP 仍是下一轮才进池、宿主策略才算授权。
  • worktree 仍不是沙箱。模型仍不能移除它。

过关句

集成 = 同一个循环 + 规定事件从哪进、从哪回。 叫醒你的是 CLI 的事件循环，不是每一个单章机制自己会叫模型。
