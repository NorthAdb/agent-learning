s14：MCP Tools

连接只发现工具；带前缀的名字要到下一轮组池时才交给模型。

来源： s14 README L35–153； code.py L316–419。

一张图

本轮 tools = 五个基础工具 + connect_mcp
  ↓
connect_mcp("docs")  →  mcp_clients 多一个 client
  ↓
下一轮 assemble_tool_pool
  ↓
mcp__docs__search / mcp__docs__get_version
  ↓
permission 查宿主表，不查 readOnlyHint
  ↓
call_tool(原始名)  →  tool_result

名字

  • 格式：mcp__{服务器}__{工具}。调用 server 时用原始名。
  • 非法字符变成下划线。规范化后撞名或超过 64 字符：组装抛错，这轮停住。
  • lambda 用默认参数绑住当时的 client 和原始工具名。

授权

  • docs 的 search、get_version，deploy 的 status：allow。
  • deploy 的 trigger：confirm。
  • 表里没有的 mcp__ 工具：confirm。
  • readOnlyHint 不参与判断。

不负责

  • 没有真实传输。只有进程内的 docs 和 deploy。
  • 再次连接同名服务器不会刷新，只返回 already connected。
  • 不带任务、团队、后台、cron。那些在 s15 才和这条池子合并。

过关句

MCP = 下一轮才进工具池 + 前缀名 + 宿主授权。 server 的自我说明不是许可。漏参数是一条错误结果，不是进程崩溃。
