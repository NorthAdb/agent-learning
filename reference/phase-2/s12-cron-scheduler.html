s12：Cron Scheduler

保存五段表达式和 prompt；进程活着时到点入队，Agent 空闲再送进循环。

来源： s12 README L52–126； code.py L263–728。

一张图

schedule_cron     validate_cron 通过才写入 scheduled_jobs
  ↓
每秒              cron_matches(本地时间)
  ↓
写盘成功          pending_delivery + last_fired，再进 cron_queue
  ↓
抢到 agent_lock   追加用户消息 [Scheduled] prompt
  ↓
模型调用成功      重复任务清 pending；一次性任务删除
模型调用失败      删掉刚追加的消息，放回队列

五段

分  时  日  月  周
0   9   *   *   *      每天 09:00
*/5 *   *   *   *      每 5 分钟，余数为 0
0   9   *   *   1-5    周一到周五 09:00
0   9   1   *   1      每月 1 日或周一的 09:00
  • 没有秒。星期 0 是周日，6 是周六。
  • 日和星期都不是 * 时，匹配是或。
  • 形状：*、*/N、N、N-M、N,M。

交付

  • 同一分钟：last_fired 或 pending_delivery 挡住第二次入队。
  • 用户回合占锁时，队列线程下一拍再试。
  • 至少一次指 prompt 被模型收下。确认在工具执行之前。
  • 定时回合里，需要 Allow? 的操作直接拒绝。

不负责

  • durable 只留定义。进程关了不补跑错过的分钟。
  • 导入模块不启动调度线程。
  • 没有 s11 后台 Bash。本章不把命令输出送进队列。

生产化补丁（s12 之后）

本课机制是对的，缺的只有一件事：计时器待在 Agent 进程里。成熟产品把调度切成三层—— 调度面（谁来计时，独立于 Agent 进程）／投递面（到点只入队，绝不打断正在跑的回合）／ 执行面（可抛弃的一次 run / session）。

要补的关键词常见做法
漏跑catch-up / misfire不补 / 只补最近一次 / 回填一段时间
撞车overlap policy排队 / 跳过 / 取消上一次 / 允许并行
整点风暴jitter按任务 ID 加确定性偏移；别挑 :00
成本过期 + 上限周期任务 N 天过期、每会话任务数上限
审批non-interactive全自动 / 每任务权限模式 / 直接拒绝
安全untrusted payload外部传入文本当数据，只有存好的 prompt 算授权

hook 做不到这件事。hook 挂在生命周期事件上（UserPromptSubmit / PreToolUse / PostToolUse / Stop…），命令 hook 不能触发 / 命令或工具调用，也就不能自己发起一轮。 Claude Code 的做法是专门加 CronCreate / CronList / CronDelete 和一个每秒检查的调度器。

三档部署（会话内 / 本机常驻 / 托管云）： Run prompts on a schedule、 Desktop scheduled tasks、 Routines。 其它产品： Temporal Schedules、 LangGraph cron、 ChatGPT tasks。 hook 事件清单：Hooks reference。

别忘了：绿点只表示 run 起停没有基础设施错误，不代表 prompt 里的任务成功。 确认的是 prompt 交付，不是工作产品。

过关句

闹钟 = 五段表达式 + 到点入队 + 空闲再交付。 落盘不是操作系统定时器；模型收下 prompt 也不等于工作做完。
