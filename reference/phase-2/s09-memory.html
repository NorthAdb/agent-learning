记录格式

---
name: user-preference-tabs
description: User prefers tabs for indentation
type: user
---

User prefers using tabs, not spaces, for indentation.
type适合保存
user用户长期偏好
feedback以后仍适用的工作反馈
project稳定项目事实
reference外部资料或查找线索

存储规则

  1. memory_slug(name)：小写化，把非单词字符替换为 -，去掉两端分隔符。
  2. memory_path(filename)：拒绝带目录的 filename；resolve() 后用 is_relative_to(MEMORY_DIR) 检查根目录边界。
  3. write_memory_file()：写完整记录后立即 rebuild_memory_index()。
  4. 索引是派生状态；正文文件才是记录来源，索引损坏时可以重建。

slug/path L84–103； 写入/index L146–186。

召回规则

list_memory_files()
  → catalog(name + description)
  → 模型返回 JSON 下标
  → 校验整数、范围、去重
  → load_memories()
  → 正文累计最多 20000 字符
  • 最多选择 5 条记录。
  • 选择模型失败或 JSON 解析失败，退回关键词命中。
  • 关键词降级只查 name + description，不是向量语义检索。
  • 召回记忆是 background knowledge，不是新命令；当前用户请求优先。

关键词 L264–278； 选择/召回 L280–330。

提取规则

Stop 且没有 tool_use
  → extract_memories(messages)
  → validate_memory_record(..., require_scope=True)
  → should_store_memory()
  → write_memory_file()
  → 若有新增，再尝试 consolidate_memories()

允许持久化：scope == "persistent"。

只限本轮：scope == "current_task"，如“本次不要创建文件”。

拒绝条件：不是 dict；字段缺失；type 不在四类中；包含 session/task/暂时等标记；slug、description 或 body 重复。

持久性检查 L108–140； 提取 L388–445； loop 接入 L740–751。

整理与恢复

  • CONSOLIDATE_THRESHOLD = 10：记录数未达到时不整理。
  • 整理模型负责合并重复、应用较新修正、删除无用信息。
  • 返回结果必须非空、每条合法、slug 不重复。
  • 替换前保存所有旧记录内容的 snapshot。
  • 删除或写入失败：删除半成品、写回 snapshot、重建索引、重新抛错。
  • 快照保证可恢复，不保证整理后的事实正确。

consolidate L450–532。

过关句

Memory = 选择性存储 + 相关召回。 不保存所有 transcript；不把临时命令变成永久规则；不让旧记忆覆盖当前请求。
