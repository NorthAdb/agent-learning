s06：Subagent

子 Agent 使用独立 messages 处理明确子任务；父子共享进程、WORKDIR 和文件副作用， 但父只收到子 Agent 的最终文本。

来源： s06 README L23–29； code.py L240–322。

一张图

父 messages
    ↓ task(prompt)
run_subagent
    ↓ 新建 child messages
子 Agent：模型 → 基础工具 → tool_result → 模型
    ↓ 最终 text
父侧 task tool_result → 父 messages

三条边界

边界当前实现
消息父 / 子各自有 messages；子内部工具结果不复制给父。
进程与工作区同一 Python 进程、同一 WORKDIR；子写文件，父随后可读。
能力父有 BASE_TOOLS + task；子只有 BASE_TOOLS，没有 task。

工具表

SUB_TOOLS = list(BASE_TOOLS)
SUB_HANDLERS = dict(BASE_HANDLERS)

TASK_TOOL = {"name": "task", ...}
TOOLS = [*BASE_TOOLS, TASK_TOOL]
TOOL_HANDLERS = {**BASE_HANDLERS, "task": run_subagent}
  • TOOLS / SUB_TOOLS：发给模型看的工具说明。
  • TOOL_HANDLERS / SUB_HANDLERS：本地按工具名执行的函数表。
  • 父的 map 有 "task": run_subagent；子的 map 没有 task，因此只有一层委派。
  • list(BASE_TOOLS) / dict(BASE_HANDLERS) 新建外层容器，不创建新进程。

源码 L256–257； L310–322。

execute_tool 共用边界

blocked = trigger_hooks("PreToolUse", block)
if blocked:
    return str(blocked)

handler = handlers.get(block.name)
output = handler(**block.input) if handler else f"Unknown: {block.name}"
trigger_hooks("PostToolUse", block, output)
return str(output)
  • 父传 TOOL_HANDLERS，子传 SUB_HANDLERS。
  • 父子基础工具都经过共享的 PreToolUse / PostToolUse hooks。
  • Pre 被拒绝时提前返回，不执行 handler，也不触发 Post。

源码 L240–252。

子循环算法

  1. 打印 started，创建 messages = [{"role": "user", "content": prompt}]。
  2. 最多 for _ in range(30) 次请求模型，使用 SUB_SYSTEM、子 messages、SUB_TOOLS。
  3. 把 assistant response 追加到子 messages，并筛选 tool_use。
  4. 有 tool_use：逐个执行、用原 id 组装 tool_result，一批回填子 messages。
  5. 无 tool_use：触发 Stop；放行后提取 text 并返回。
  6. 30 轮仍未最终回答：返回 Subagent stopped after 30 turns without a final answer.。

源码 L270–307。

extract_text

if not isinstance(content, list):
    return str(content)
return "\n".join(
    getattr(block, "text", "")
    for block in content
    if getattr(block, "type", None) == "text"
)
  • 只在没有 tool_use 的结束分支拿最终文本。
  • 只拼接 type == "text" 的 block；不返回子 messages。
  • 没有文本时，调用方用 or "(no summary)" 提供兜底。

对父循环来说，task 仍是普通工具：handler 返回子最终文本后， 父用原 task 的 id 回填 tool_result，再请求父模型。 子的中间调用不会自动进入父 messages。

最容易混淆的六组关系

  • fresh messages ≠ 新进程：只隔离对话。
  • 消息隔离 ≠ 文件隔离：WORKDIR 共享。
  • task ≠ bash：task 开一个子循环，子循环再决定是否调用 bash。
  • 最终 text ≠ 验证证据：父仍要 read / bash / test。
  • 30 turns ≠ 全局 max_turns：只限制一次子循环，父仍是 while True。
  • 子没有 task ≠ 子不能执行工具：子仍拥有五个基础工具。

调用时机

UserPromptSubmit外层 REPL 提交用户输入时本实现不会因子 prompt 自动触发
