ContextCompactor 方法地图

code.py L247–521； 详细讲解见 0028 课件 · ContextCompactor 节。

组合方法用途
A 转存 persist_large_output → persisted_preview → save_output / persisted_output_path 全文落盘，消息留路径+预览
B 归档 has_tool_use / is_tool_result / is_archive_marker + write_transcript + snip_compact 消息过多时头尾保留，中间进 transcript
C 微压缩 unseen_tool_result_positions + estimate_chars + micro_compact 缩短较早已消费结果
D 摘要 summary_input + summarize_history + summary_message + write_transcript 被 compact_history / reactive_compact 复用
E 入口 prepare（请求前）；旁路 reactive_compact / compact_history 编排 A–D；API 拒绝与主动 compact 走旁路

叶子函数（识别、落盘）不要先读；从 prepare 和 agent_loop 往下跟调用。

阈值

常量含义
CONTEXT_CHAR_LIMIT=50000消息 JSON 字符近似的上下文阈值
TOOL_RESULT_BATCH_CHAR_LIMIT=200000最新工具结果批次预算
LARGE_RESULT_CHAR_LIMIT=30000单条结果超过此值可转存
KEEP_RECENT_RESULTS=3微压缩保留最近三条已消费结果
KEEP_RECENT_MESSAGES=5API 拒绝后的 reactive compact 保留最近消息
max_tokens=8000模型本轮输出上限，不是输入窗口或轮数上限

四步规则

  1. budget：只处理最新 user 工具结果批次；按大小从大到小，完整输出存入 .task_outputs/tool-results/，消息留路径和预览。
  2. snip：超过 50 条时写完整 .transcripts/，保留头 3、尾 46 和一个 archive marker；切点保护 tool_use / tool_result 配对。
  3. micro：只缩短较早且已被模型消费的长结果；完整内容已保存，消息替换为恢复路径。
  4. fit：若最新未消费结果自己就撑爆上下文，写盘并留 1000 字符预览。
  5. summary：仍超限才调用模型；摘要是有损继续工作状态，完整 transcript 才是备份。

budget L360–378； snip L390–410； micro L410–452； prepare L510–521。

API 拒绝补救

try:
    messages.create(...)
except Exception as error:
    if "prompt_too_long" in str(error).lower():
        reactive_compact(...)
        retry once
    else:
        raise
  • 字符估算只是近似，服务端仍可能拒绝。
  • reactive_compact 保存 transcript、摘要旧历史、保留最近 5 条。
  • MAX_REACTIVE_RETRIES=1 防止无限压缩循环。

过关句
