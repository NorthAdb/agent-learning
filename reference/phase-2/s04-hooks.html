s04：Hooks

扩展逻辑挂在循环上；循环只触发事件，不知道每个扩展函数的名字。

来源： s04 README L38–52； code.py L128–138。

一张图

UserPromptSubmit
        ↓
      LLM → PreToolUse → handler → PostToolUse → tool_result → LLM
        ↓（本轮没有 tool_use）
      Stop → None: return / 非 None: append 消息并 continue

核心注册表

HOOKS = {
    "UserPromptSubmit": [],
    "PreToolUse": [],
    "PostToolUse": [],
    "Stop": [],
}

def register_hook(event: str, callback):
    HOOKS[event].append(callback)

def trigger_hooks(event: str, *args):
    for callback in HOOKS[event]:
        result = callback(*args)
        if result is not None:
            return result
    return None
  • event = 什么时候触发；callback = 事件发生时调用的函数。
  • 注册传 callback，不要写 callback()；前者保存函数，后者立即执行。
  • 定义处 *args 打包，调用处 callback(*args) 解包；同一触发器才能转交 1 个或 2 个参数。
  • callback(*args) ≠ callback(args)：后者把整个元组当成一个参数。
  • 按注册顺序运行；第一个非 None 结果会短路后续 callback。

四个事件

事件参数当前 callback返回值效果
UserPromptSubmit query context_inject_hook（实际只打印 WORKDIR） 当前入口忽略
PreToolUse block permission_hook → log_hook 非空拒绝：回填 tool_result，跳过 handler
PostToolUse block, output large_output_hook 当前只观察 / 提醒，返回值忽略
Stop messages summary_hook None 放行 return；非空阻止退出并 continue

PreToolUse 的真实顺序

blocked = trigger_hooks("PreToolUse", block)
if blocked:
    results.append({
        "type": "tool_result",
        "tool_use_id": block.id,
        "content": str(blocked),
    })
    continue

handler = TOOL_HANDLERS.get(block.name)
output = handler(**block.input) if handler else f"Unknown: {block.name}"
trigger_hooks("PostToolUse", block, output)
  1. 权限 hook 返回 None → 继续日志 hook。
  2. 权限 hook 返回拒绝字符串 → 触发器短路，日志 hook 也不跑。
  3. 拒绝仍必须使用原 block.id 回填 tool_use_id。
  4. Post hook 当前没有修改 output 的通道。

和 s03 的一句对照

s03：循环直接调用 check_permission(block)。 s04：循环调用 trigger_hooks("PreToolUse", block)， 权限逻辑作为 permission_hook 注册。语义仍是执行前拦截， 变化是扩展不再侵入循环。

四个检查问题

  • hook 没注册会运行吗？不会；必须注册且必须在正确时机触发。
  • Stop 什么时候触发？只有本轮没有 tool_use、准备退出时。
  • context_inject_hook 真注入了吗？没有；当前只打印。
  • hook 系统等于安全沙箱吗？不等于；安全效果取决于实际检查和执行边界。
