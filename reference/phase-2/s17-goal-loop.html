s17：Goal Loop

模型想停时，独立判断器只根据对话决定完成、继续，或把人叫回来。

来源： s17 README L21–147； code.py L354–422。

一张图

还有 tool_use → 执行，不判断
没有 tool_use 且没有目标 → allow，返回
后台还在跑 → defer，不调用判断器
ok → achieved，清除目标
impossible → failed，清除，但不是完成
没完成 → block，理由写回同一份 messages
连续 block 超 cap → limit，目标还在
判断器抛错 → error，目标还在
MAX_TURNS 到了 → max_turns，目标还在

命令

  • /goal 条件：替换并立刻开工。条件最长 4000 字。
  • /goal：查看次数、时间、token、最近理由。
  • /goal clear：清除。别名 stop、off、reset、none、cancel。

不负责

  • 判断器不能读文件、不能跑测试。
  • 不是测试框架。证据要主模型写进对话。
  • CLI 不持久化会话。restore 只恢复仍活跃的条件，计数和时间重来。
  • workflow 结束没有特殊豁免。

过关句

想停 ≠ 做完。 判断器只读对话。上限把人叫回来，不把目标改成已完成。
