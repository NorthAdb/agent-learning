s11：Background Tasks

只有明确要求的 Bash 先交回编号；命令输出以后再作为通知送进对话。

来源： s11 README L13–136； code.py L318–491。

一张图

PreToolUse                 主线程审批；拒绝则没有 bg_id
  ↓
should_run_background      bash 且 run_in_background is True
  ↓
start                      登记 bg_0001，守护线程跑命令，立刻返回
  ↓
tool_result                占位句子。这一次 tool_use 到此结束
  ↓
下次 messages.create 之前
  ↓
task_notification          文本，不带原来的 tool_use_id

判断

  • 进后台：工具名是 bash，并且参数是布尔 True。
  • 不进后台：缺省、False、字符串 "true"、数字 1、install/build/test 关键词、读/写/改/glob。
  • run_bash 收下该参数后仍然同步。分叉在 execute_tool 里，进后台时不会调用 run_bash。

登记表

bg_0001
  status: running → completed | failed
  只在这次进程的内存里
  收集后从 tasks / results 删除
  • 退出码 0：completed。
  • 非零、120 秒超时（退出码 None）、线程异常：failed。
  • 进程输出先截到 50000 字符；通知 summary 再截到 500。
  • 没有列出后台任务的工具。模型只看见占位句子和后来的通知。

什么时候看得见

  • 同一次提问里模型还在调工具：下一次请求模型之前，通知贴在上一条 tool_result 用户消息上。
  • 模型已经停住：要等你再输入一句，再次进入 agent_loop。
  • 命令完成不会打断正在进行的模型调用，也不会自己再问一轮。
  • 同一条回复里的下一个工具不必等后台命令结束；模型仍要等整批 tool_result 一起回来。

不负责

  • 不把 s10 任务图放进后台。本章工具仍是 s04 的五个。
  • 进程组清理不是沙箱。os.killpg 是 Unix 接口。
  • 不定时。完成也不证明工作做完。闹钟是 s12。
