s07：Skill Loading

system prompt 放技能目录；模型需要时调用 load_skill(name)， 完整 SKILL.md 才作为 tool_result 进入 messages。

来源： s07 README L30–40； code.py L51–136。

一张图

启动
  ↓
scan skills/*/SKILL.md
  ↓
registry: name → description + cached content
  ↓ catalog()
system: 技能名 + 简介

模型 → load_skill(name)
  ↓
registry 查表 → 完整 SKILL.md
  ↓
tool_result → messages → 模型下一轮

三层边界

层保存什么何时进入模型
system 所有技能的 name + description 启动构造 SYSTEM；每轮都作为静态前缀发送
registry name、description、完整 content 的本地字典 不直接发送；由 catalog / load 读取
messages load_skill 的完整正文 tool_result 调用工具并回填后；之后随历史继续携带

“按需”在本课指按需注入模型上下文；scan 启动时已经把全文读入内存。

Skill 文件形状

---
name: code-review
description: Perform thorough code reviews...
---

# Code Review Skill
正文指令、清单、示例...
  • frontmatter：两条 --- 之间的 YAML metadata。
  • name：registry 的键；缺失或无效时回退到父目录名。
  • description：目录简介；缺失时回退到正文第一行。
  • content：保存原始全文，load 时返回全文，不只返回 body。

scan 算法

  1. self.skills.clear() 清空旧 registry。
  2. 目录不存在 → 返回；catalog 显示 (no skills found)。
  3. sorted(skills_dir.glob("*/SKILL.md")) 只扫直接子目录。
  4. 用 resolve().is_relative_to(skills_root) 确认文件仍在根目录内。
  5. UTF-8 读全文，解析 frontmatter。
  6. 保存 {"name", "description", "content"} 到 self.skills[name]。

catalog 与 system

def catalog(self) -> str:
    if not self.skills:
        return "(no skills found)"
    return "\n".join(
        f"- {skill['name']}: {skill['description']}"
        for skill in self.skills.values()
    )

SYSTEM = build_system_prompt()
# build_system_prompt 中嵌入 SKILL_LOADER.catalog()
  • catalog 只拼 name + description，不拼 content。
  • catalog 是发现能力，不是完整技能正文。
  • SYSTEM 在启动时构造；本课没有自动热更新。

load 算法

def load(self, name: str) -> str:
    skill = self.skills.get(name)
    if skill:
        return skill["content"]
    available = ", ".join(self.skills) or "none"
    return f"Error: Unknown skill '{name}'. Available: {available}"
  • 按字典键精确匹配；不把 name 当路径。
  • 命中 → 返回启动时缓存的原始全文。
  • 未命中 → 返回错误字符串和可用名称，不抛未捕获异常。
  • 大小写、空格、别名不自动归一化。

工具接线

TOOLS:
{
  "name": "load_skill",
  "description": "Load the full SKILL.md content by skill name.",
  "input_schema": {
    "type": "object",
    "properties": {"name": {"type": "string"}},
    "required": ["name"]
  }
}

TOOL_HANDLERS:
"load_skill": SKILL_LOADER.load
  • schema 给模型看；handler 给 Harness 执行。
  • 注册函数对象 / 绑定方法，不写 SKILL_LOADER.load()。
  • handler(**block.input) 等价于 load(name="code-review")。

最容易混淆的八组关系

  • 技能目录 ≠ 技能全文：前者进 system，后者经 load_skill 进 tool_result。
  • 按需注入 ≠ 按需读磁盘：本课启动 scan 已缓存全文。
  • Skill ≠ Python 函数：Skill 是 Markdown 指令文档。
  • Skill ≠ 项目事实：技能告诉怎么做，read_file / bash 提供实际观察。
  • name ≠ path：load 只查 registry，不打开任意输入路径。
  • resolve ≠ 拒绝：resolve 规范化；is_relative_to 判断；if/continue 跳过。
  • schema ≠ handler：schema 是契约；handler 才查表返回正文。
  • load 完整正文 ≠ 自动执行：文档中的命令仍需另一个 tool_use。

过关句

Skill Loading = 目录常驻 + 正文按需进入消息轨迹。 它减少启动时的无关上下文，但不替代工具执行、权限检查、事实读取和完成验证。
