分支与循环：最小 Agent loop

Coding agent 的心脏不是「写一段 prompt」，而是一个循环：模型决策 → 调工具 → 观察结果 → 再决策。 今天的主技能是 Python 的 if / for / while； 载体是一个假的 tool loop，形状对齐你以后要读的 North s01。

和 Java 怎么对照

  • Python 用缩进定代码块，没有 { }。少一级或多一级空格都会 IndentationError 或逻辑错位。
  • if / elif / else ≈ if / else if / else；条件不写括号也可以，但冒号 : 不能少。
  • for x in seq ≈ 增强 for：直接遍历元素，不是 C 风格的 for (i=0; ...)（那种用 range）。
  • while 同名；Agent loop 几乎总是 while，因为「几轮结束」由模型决定。
  • break / continue 语义与 Java 相同。

概念展开

1. 分支：同一入口，不同出路

顺序执行解决不了「工具叫什么名字 / 消息是 final 还是 tool_calls」。分支让程序在运行时选路：

if name not in TOOLBOX:
    return {"ok": False, "error": "..."}
# 只有通过检查才会执行到真正调用

elif 用于互斥的多路（先匹配先走）；一连串独立 if 可能连续命中多条——读 harness 时要分清作者意图。

2. for：集合已知时遍历

一轮模型回复里经常带 多个 tool_calls。用 for 逐个执行（真实系统里也可能并行，但控制流仍是「对列表做一遍」）：

for call in msg["tool_calls"]:
    out = run_tool(call["name"], call["arguments"])

3. while：圈数未知 + 必须能停

写死 for _ in range(2) 太脆：模型可能一轮就 final，也可能工具来回十几轮。典型写法：

while turn < max_turns:
    msg = model(...)
    if msg["type"] == "final":
        break
    ...
    turn += 1
  • 正常出口：收到 final → break
  • 安全带：max_turns 触顶，防止死循环烧钱/挂死

    • if type == "final"：打印并 break

    • 其它 type：防御性打印后 break

常见坑

  • 缩进混用 Tab/空格 → 诡异语法错。本仓脚本已统一空格。
  • 忘记在工具分支里 turn += 1 → 同一 turn 死循环（假模型会一直返回同一句）。
  • 只有 while、没有 max_turns → 模型若从不 final，进程不结束（真 harness 还会叠加超时/费用熔断）。
  • 把 for 当 while 用：圈数其实不固定时，硬写 range(N) 会截断或空转。
