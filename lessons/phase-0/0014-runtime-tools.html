系统讲解

1. getattr：按名字读对象属性（可给默认）

1.1 它是什么？

getattr 是内置函数：getattr(对象, "属性名", 默认值)。 用字符串指定属性名；有则返回该属性的值；没有则返回默认值（不写默认值则 AttributeError）。 

getattr(block, "type", None)   # 有 type → 其值；没有 → None
block.type                     # 写法更短，但没有就崩

1.2 解决什么问题？为什么 s01 要写它？

Anthropic SDK 返回的 content 里每一项往往是对象（有 .type、.text），不是 dict。 Agent loop 要判断「这是文本块还是 tool_use」，但有的块可能没有某个字段。 硬写 block.type 会在缺字段时炸掉；写成 block["type"] 则对对象直接 TypeError。 

# North s01 真实用法（大意）：
if getattr(block, "type", None) == "text":
    print(block.text)

作用：一次完成「取值 + 缺失时给默认」，loop 不会因为形状略变就崩。

1.3 三案对照（必背）

案写法适用缺了怎么办
① obj.type 确定是对象且字段一定在 AttributeError
② data["type"] 确定是 dict 且键一定在 KeyError；对对象用 [] → TypeError
③ getattr(obj, "type", None) 对象；字段可能没有 返回默认值，不崩 
class Block:
    def __init__(self, type: str, text: str | None = None) -> None:
        self.type = type
        self.text = text

obj = Block("text", "hello")
data = {"type": "text", "text": "hello"}

obj.type                         # ① OK
data["type"]                     # ② OK
getattr(obj, "type", None)       # ③ → "text"
getattr(obj, "missing", None)    # ③ → None（不崩）
# data.type  → AttributeError（dict 没有这种属性访问）
# obj["type"] → TypeError（普通对象不支持下标）

hasattr(obj, "type") 只回答有没有。s01 用 getattr 一次拿值。 dict 请继续用 .get（0006）——不要对 dict 用 getattr 当主路径。

1.4 哪些类型能用？（不是「只用于类」）

getattr 面向的是对象——Python 里几乎什么都是对象，不限于你自己写的类。 列表、元组、字符串、整数、字典都能用，但取的是它们身上的属性/方法名， 不是容器里的「第几个元素 / 哪个键」。

你学过的类型getattr 能取什么取「里面的元素」用什么
list方法名，如 "append"、"sort"xs[0]
tuple方法名，如 "count"、"index"t[0]
str方法名，如 "strip"、"upper"s[0] 或切片
dict方法名，如 "get"、"keys"d["k"] / d.get("k")
int / bool少数属性/方法，如 "real"一般不靠下标
自定义类实例你设的字段，如 "type"点号或 getattr（本课主场景）
getattr([1, 2], "append")       # 拿到 append 方法（能用，日常直接 .append）
getattr((1, 2), "count")
getattr("hi", "upper")
getattr({"a": 1}, "get")        # 拿到 get 方法
getattr({"a": 1}, "a", None)    # → None：键 "a" 不是属性！

口诀：基本类型都能 getattr「身上的方法」；容器里的内容仍用下标或 .get。 本课 Agent 场景要记的是：SDK block → 属性用 getattr；dict 载荷 → 用 .get。

1.5 setattr（顺带认）

setattr(obj, "k", v)：按字符串写属性，等价于 obj.k = v。 本课主脚本用它组装 FakeBlock（模仿 SDK 对象）。见到能懂即可，不是 North 主路径。

2. subprocess.run：起子进程并等它结束

2.1 它是什么？

subprocess = 在当前 Python 进程里，再拉起一个操作系统进程（跑 python、git、bash…）。 subprocess.run(...)：启动 → 等结束 → 返回一个结果对象（含 returncode / stdout / stderr）。 Agent 的「bash 工具」本质就是这个。

2.2 解决什么问题？

模型可以「建议」执行 ls / git status，但建议不会自己改磁盘—— Harness 必须真的执行，再把输出当观察塞回对话。 没有 subprocess，就没有可用的 bash 工具。 

# North s01 run_bash 大意：
r = subprocess.run(command, shell=True, cwd=...,
                   capture_output=True, text=True, timeout=120)
out = (r.stdout + r.stderr).strip()
# 超时 → TimeoutExpired → 返回 "Error: Timeout..."

2.3 关键参数在干什么？

completed = subprocess.run(
    ["python", "-c", "print('ok')"],  # argv 列表：一个参数一个元素
    capture_output=True,               # 抓住 stdout/stderr，不要直接打到终端
    text=True,                         # 当 str，不是 bytes
    timeout=10,                        # 秒；超时抛 TimeoutExpired
    cwd="...",                         # 子进程工作目录（可选）
)
completed.returncode   # 0 通常表示成功
completed.stdout       # 标准输出文本
completed.stderr       # 标准错误文本
参数 / 字段作用不设会怎样
argv 列表程序名 + 参数，不经 shell 二次拆分见下方 shell=True
capture_output把输出接到结果对象里输出可能直接刷屏，脚本不易处理
text=Truestdout/stderr 是 str默认是 bytes，拼接/打印更麻烦
timeout防止子进程卡死拖死 agent loop可能永远等下去
returncode进程退出码；0 常表示成功只看 stdout 会漏掉失败

2.4 三案（必背）

案情况你看到
①正常结束returncode == 0，读 stdout
②命令失败（非零退出）returncode != 0；stdout/stderr 里常有原因（未必抛异常）
③超时抛 subprocess.TimeoutExpired

案 ② 很重要：很多命令失败只是 returncode ≠ 0，run 本身不抛错。 Agent 工具要把非零收成错误字符串返回（像 s01 把失败变成 tool 观察），不能假装成功。

2.5 shell=True vs argv 列表

写法谁用注意
run(["python", "-c", "print(1)"]) 本课练习；自己写脚本优先 更安全：参数不会被 shell 再拆一次
run(command, shell=True) North bash：模型吐出的是一整串命令字符串 读 North 时认即可；拼用户/模型字符串有注入风险，自己的脚本别随便开

3. glob：按通配符找文件（并和 grep 分清）

名字像：glob / grep。一个找「哪些文件」，一个找「文件里哪些行」。别混。

3.1 glob 是什么？

glob：用模式匹配文件路径/文件名。* = 任意一段字符，? = 单个字符。 两种常见入口：

  • Path("某目录").glob("*.py")：相对该目录匹配，返回 Path 迭代
  • glob.glob(完整模式字符串)：模块函数，返回路径字符串列表

本课两者都会见到；语义一样——按模式枚举文件，不是打开内容、也不是搜正文。

3.2 glob 解决什么问题？

Agent 常要「找出所有测试文件 / 所有 md」。 手写 iterdir + 后缀判断可以，但通配更短；s02 的 glob 工具就是把它暴露给模型。

3.3 和 grep 一块认（易混）

globgrep
问的问题 哪些文件名字符合模式？ 哪些行/文件正文里出现某段文字？
匹配对象 路径字符串（如 *.py、src/**/*.md） 文件内容里的文本/正则
典型调用 Python：Path.glob / glob.glob 终端命令：grep -n "timeout" *.py；或 Agent 用 bash 工具去跑
标准库有没有同名模块？ 有：import glob 没有叫 grep 的标准库模块；正文搜索用 re（0015）或调系统 grep
North s02 有专门的 glob 工具 常借 s01 的 bash / 后面读文件再搜；本课只要求能和 glob 分清 
# glob：找出名字以 .py 结尾的文件（不管文件里写了什么）
list(Path(".").glob("*.py"))

# grep（终端直觉）：在已有文件的内容里找单词 timeout
# grep -n "timeout" *.py
# 注意：这里的 *.py 是 shell 先展开文件名，再交给 grep 搜内容——
#       文件名展开 ≈ glob；搜内容 ≈ grep。两步常连着出现，所以容易混。

口诀：glob 找文件名；grep 找文件里的字。 本课主技能仍是 glob；grep 认概念即可，正文正则留到 0015 re。

3.4 关键规则：glob 找不到不是错误

here = Path(__file__).resolve().parent
list(here.glob("*.py"))     # 有则若干 Path
list(here.glob("*.nope"))   # → []  空列表，不抛异常

这和「文件不存在去 open」不同：glob 的结果集可以为空。 工具实现里应对「零命中」返回友好说明，不要当成崩溃。 （grep 找不到匹配时，系统命令常以非零退出码表示「未命中」——又是另一种约定，别和 glob 的空列表混用。）

常见坑 + 边界

  • 以为 getattr 只能用于类：list/tuple/str/dict 等对象也能用，取的是方法/属性名；容器元素仍用 [] / .get。
  • 对 SDK 对象写 block["type"] → TypeError；对象用点号或 getattr。
  • 对 dict 写 block.type → AttributeError；dict 用 [] / .get。
  • 不设 timeout：子进程卡死，agent loop 一起卡。
  • 只看 stdout、不看 returncode：失败命令也可能「看起来有输出」。
  • 以为非零退出会自动抛异常：不会；要自己检查 returncode。
  • shell=True 拼用户/模型字符串：有注入风险；教学脚本用 argv 列表。
  • glob 无匹配当成错误：空列表是正常结果。
  • 把 glob 和 grep 当成一回事：glob 匹配文件名；grep 搜文件内容。Python 有 glob 模块，没有叫 grep 的标准库模块。
