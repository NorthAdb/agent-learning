列表与元组：检索结果与候选排序

上一课的 tools.py 里，rag_search 返回 hits[:top_k]——那是检索侧。 真实 RAG 不会这么省心：候选几十上百条、分数乱序、里面混着低于阈值该扔掉的旧文档。 今天练的是拿到 hits 之后、喂给模型之前那段处理：过滤、排序、截断、拼上下文。 主技能是 Python 的列表与元组；载体是把这套操作串成一个 rank_results.py。

系统讲解

1. 为什么是这一课

你看过 tools.py 的返回了：{"score": 0.91, "text": "..."} 这种 dict 组成的一个 list。 真实检索返回的候选会长这样——顺序是乱的、分数有高有低、还夹着低分的旧文档： 

hits = [
    {"id": "d-03", "text": "Tool 是 harness 暴露的动作", "score": 0.72},
    {"id": "d-07", "text": "RAG 先检索再生成",           "score": 0.91},
    {"id": "d-01", "text": "（过期的旧文档）",             "score": 0.31},
    {"id": "d-09", "text": "上下文窗口装不下整本书",       "score": 0.84},
    {"id": "d-02", "text": "Permission 决定工具能不能跑", "score": 0.45},
]

要把它变成「给模型的上下文块」，至少要四步：过滤（丢弃低于阈值的）、 排序（按分数降序）、截断（只留 top_k）、 组装（拼成一段带编号的文本）。这四步全是列表操作。 本课先把列表摸熟，然后主脚本 rank_results.py 把四步串起来。 Python 官方教程 Data Structures 章是本课规则出处，边学边对。

2. 创建与索引

[] 字面量、list(...) 构造器都能造列表。 list(range(1, 6))、list("abc") 把别的序列变成 list； [0] * 6 造 6 个 0（乘的是不可变对象 0，所以安全）。 len(xs) 拿元素个数；索引从 0 开始，xs[-1] 从末尾数。 索引越界会 IndexError: list index out of range——和 Java 的 IndexOutOfBoundsException 是同一类：访问了一个不存在的位，直接崩。 

chunks = ["chunk-a", "chunk-b", "chunk-c"]
len(chunks)     # 3
chunks[0]       # 'chunk-a'
chunks[-1]      # 'chunk-c'  负索引从末尾数
chunks[1] = "chunk-b2"   # 列表可变：改已有位置
# chunks[9]     # IndexError: list index out of range

记住下一条再对照它。索引越界会崩，切片越界不会——这是本课第二个重点。

3. 切片：返回新 list，越界不报错

xs[start:end:step]：取从 start 到 end（不含） 、每隔 step 一个的元素。start 默认 0、end 默认长度、 step 默认 1，所以都能省。切片永远返回一个新的 list—— 这是和 Java subList 最大的差别：subList 是原列表的视图，改它会波及原列表； Python 切片是一份拷贝，原列表怎么动都不影响它。 

hits = ["a", "b", "c", "d", "e"]
hits[:3]       # ['a', 'b', 'c']   取前 3 条（截断 top_k 就靠它）
hits[1:3]      # ['b', 'c']        end 不含
hits[::2]      # ['a', 'c', 'e']   隔一个取一个
hits[::-1]     # ['e','d','c','b','a']  负步长 = 反转，得到新 list
hits[10:]      # []                越界不报错，安安静静给空 list
copy = hits[:] # 拷贝整个列表
last_3_backwards = hits[4:0:-1]  # ['e','d','c','b']  从 4 往前走到 0（不含）

0004 里 return hits[:top_k] 你已经见过：top_k 是几就留几条。 现在知道为什么它不怕超范围——切片越界只会得到更短的 list 或空 list。

4. 遍历与成员

for x in xs 直接拿元素（0003 已会用）。真正读 Agent 代码时常需要同时拿序号和元素： enumerate(xs) 每次吐一个 (序号, 元素) 的二元组，for i, h in enumerate(xs) 就是把这个二元组解包成两个变量（解包规则第 8 节系统讲）。 enumerate(xs, start=1) 让编号从 1 而不是 0 开始——给上下文编号时最常用。 

for i, h in enumerate(hits, start=1):
    print(f"#{i} {h['id']} score={h['score']}")
# #1 d-07 score=0.91
# #2 d-03 score=0.72
# #3 d-01 score=0.31

in / not in 判断成员。"d-03" in ids 是 True。zip(a, b) 把两个列表按位置配成一对对二元组： for doc_id, score in zip(ids, scores)。 注意：list 的 in 是逐项线性扫描；到 0006 你会看到集合 set 的 in 是哈希查找，快得多——数据大了别拿 list 当去重工具。

5. 增删与拼接：append 和 extend 是两回事

方法做什么找不到 / 越界时
xs.append(x)把 x 作为一个元素加到末尾—
xs.extend(ys)把序列 ys 的每个元素逐个并入—
xs.insert(i, x)插到位置 i，原位置及之后后移—
xs.remove(x)按值删第一个匹配ValueError（先 in 判断再删）
xs.pop(i)按位置删，并返回被删元素（默认删末尾）越界 IndexError
xs.clear()清空—

append 和 extend 是最容易混的一对，差别在「把什么当一个元素」：

pool = []
pool.append(["d-02", "d-03"])     # 整个 list 当一个元素：pool 变成嵌套
print(pool)                       # [['d-02', 'd-03']]

pool = []
pool.extend(["d-02", "d-03"])     # 元素逐个并入：展平
print(pool)                       # ['d-02', 'd-03']

上面 pool = [] 那行是重新绑定——不是清空。想要真正清空用 pool.clear()；重新绑定后，原来那个 list 对象还在（如果你的函数还引用着它）。 append 想要的是「整体收下这份结果」；extend 想要的是「把它里面的结果收进来」。 收集候选时常用 extend，把一批结果并进总量。

xs + ys 拼出一份新 list（原两个不动）；xs += ys 原地并入，等价 extend。 del xs[i] 也能按位置删（不返回被删的值），底层比 pop 略快，但 Agent 代码里 pop 更常见。

6. 排序：sort 原地、sorted 返回新 list，以及按字段排

xs.sort() 原地改 xs，而且返回 None； sorted(xs) 返回一份新排好序的 list，原列表不动。 这是本课最该背下来的坑：xs = xs.sort() 会把你的变量从 list 变成 None—— 对照 Java，Collections.sort 也是原地 + void，但那没有「把返回值赋回变量」的诱惑； Python 里 sorted 和 sort 一个给新、一个原地，先分清再用。 

scores = [0.72, 0.91, 0.45]
print(sorted(scores))    # [0.45, 0.72, 0.91]  新 list，scores 没动
print(scores)            # [0.72, 0.91, 0.45]  原样
scores.sort()            # 原地改 scores
print(scores)            # [0.45, 0.72, 0.91]
x = scores.sort()        # x 是 None！别把 sort() 的结果赋回去

对 list[dict] 按字段排，用 key= 参数告诉排序逻辑「拿每个元素的哪块当比较键」： 

ranked = sorted(hits, key=lambda h: h["score"], reverse=True)
# 结果：score 从大到小；reverse=True 表示降序
# lambda 在 Day16 系统讲；这里只要知道它返回「这个元素的排序键」
# 那句手写 while 树的同款意思：比较时按 h["score"] 而不是按整个 dict

min(xs) / max(xs) / sum(xs) 拿极值和总和。 xs.index(x) 找第一处位置（找不到 ValueError）； xs.count(x) 数出现次数（找不到给 0，不异常）。

7. 列表生成式：过滤 + 投影一行完成

[表达式 for 变量 in 序列 if 条件] 把「建一个空列表 → 循环 → 判断 → append」折叠成一行。Day09 给的理由：不只是好看，字节码里专门有生成式的指令，比循环 + append 更快。 结论记住一条：生成式造列表，别手写三行空列表 + append。 

# 只要 id：投影
ids = [h["id"] for h in hits]
# 只要分数够的 text：过滤 + 投影
ok = [h["text"] for h in hits if h["score"] >= 0.5]
# 和 Java 对照：filter(...).map(...) 接一个 List.collect，同一件事

嵌套列表（list 里套 list，矩阵、成绩表）访问要两层索引：scores[0][1]。 读真实代码最常见的是 list[dict]：hits[0]["score"]、[h["id"] for h in hits]—— 一层索引拿 dict，再一层拿字段。本课主脚本就是这种形状。

8. 元组与解包

元组 (x, y, z) 是不可变的序列：能索引、切片、len、 in，但 不能改——t[0] = ... 直接 TypeError。 Java 里没有直译；最接近的是「final 字段组成的 record / 不可变 List」。 

pair = ("d-07", 0.91)     # 二元组：id + 分数，通常一批数据结成对
single = ("only", )       # 一元组：逗号不可省！("only") 是 str 不是 tuple
empty = ()                # 空元组

元组的招牌动作是解包——把元组（其实任何序列）拆开喂给多个变量：

doc_id, score = pair      # doc_id="d-07", score=0.91
a, b = b, a               # 交换两个变量，不用中间变量
first, *rest = [1, 2, 3, 4]   # first=1, rest=[2, 3, 4]；*rest 收走剩下的，得到一个 list
status, data = call_api()     # 函数返回二元组，调用方一行拆开
# a, b, c = (1, 2)         # ValueError: not enough values to unpack

解包数量对不上立刻 ValueError——这是保护，不是麻烦：函数改签名时，该有的字段少一个都会当场暴露。 第 4 节的 for i, h in enumerate(hits) 就是在解包每个 (序号, 元素) 二元组。

为什么已有 list 还要元组？教材给了理由，挑三个对 Agent 有用的：

  • 不可变 → 可哈希：元组以后能直接当 dict 的 key（0006 讲字典时你会用到「(类型, 消息) 当 key」）；list 永远不行。
  • 多返回值：函数只 return 一个对象，但「返回一个二元组」配合调用方解包，就长成了多返回值的用法。
  • 更省：创建元组比 list 快（Day10 有 timeit 对比，数量级差别）；一旦定型、不会再改的数据，用元组是「声明了意图」。

list(pair)、tuple(xs) 随时互转；克制点用，不要来回倒腾。

9. 嵌套：真实数据的形状

真实 harness 里的数据很少是扁平的 [1, 2, 3]，多是「容器套容器」。 本课先认熟两种，动手读代码时不要被吓到： 

# list[dict]：检索结果列表，每个元素是一个「命中」
hits = [
    {"id": "d-07", "text": "RAG 先检索再生成", "score": 0.91},
    ...
]
hits[0]["score"]        # 先一层索引拿 dict，再一层拿字段
ids = [h["id"] for h in hits]   # 俯视整个列表：它就是一批 dict，生成式直接投影

# list[list]：矩阵 / 分批数据
scores = [[95, 83, 92], [80, 75, 82], [92, 97, 90]]
scores[0][1]            # 83

读法口诀：一层花括号一层索引/循环。list[dict] 就「外层 for 循环，内层用键」； 别急着把两层合并成一个动作，先把「哪层是 list、哪层是 dict」指出来。

主脚本导读（rank_results.py）

主脚本把「拿到 hits 之后」的四步走一遍。四个文件对齐以后要读的开源 agent / RAG 段： 检索层（工具）只负责「找候选」，组装层负责「挑该用的」，最后才是 prompt。

  1. 跑入口： 
    python 0005-lists-tuples\rank_results.py
    输出五大段：原始候选 → 过滤 → 排序 → top 3 → 上下文块。对照每一步的 id 列表，确认每一步都按预期变了。
  2. fetch_hits() 返回的是乱序候选——故意的。真实检索不会替你排好。 0.31 的 d-01 和 0.45 的 d-02 是会拖累回答的旧文档：上下文窗口有限，喂进去越干净，模型回答越准。
  3. 过滤（第 1 步）用的就是列表生成式的「过滤」半边： 
    passed = [h for h in hits if h["score"] >= threshold]
    把「不要低分」写成了条件。想多删一类（比如排除过期 id），就在 if 里加一个条件。
  4. 排序（第 2 步）：sorted(..., key=...) 不动 passed 本身（所以第 3 步还能安全地拿它当原始顺序）；reverse=True 是我们想要的降序。 hits.sort() 这种原地版在这里没有意义——我们希望保留一份处理前的顺序做对照。
  5. 截断（第 3 步）ranked[:top_k]：和 0004 里 hits[:top_k] 一模一样的切片；现在你知道它不怕越界了。
  6. 组装（第 4 步）两件东西分别预告 0006： 
    lines = [f"[{i}] ({h['score']:.2f}) {h['text']}" for i, h in enumerate(top, start=1)]
context = "\n".join(lines)
    enumerate(top, start=1) 吐出 (1, 第一条)、(2, 第二条)， for i, h 解包它们；.join 是字符串方法——把 lines 这个 list[str] 用换行拼成一段文本。字符串方法 0006 系统讲，这里先当用法记住。 拼出来的就是「要往系统提示词里塞的上下文块」——本课从检索到上下文的最小 RAG 切片。

常见坑 + 边界

  • 索引越界 vs 切片越界：xs[10] 崩（IndexError），xs[10:] 给 []。先分清你写的是哪个。
  • xs = xs.sort()：sort 原地改并返回 None，这行把你变量毁了。要新 list 用 sorted、要原地用 sort 然后别接返回值。
  • append 塞进整个列表：pool.append(["a","b"]) 变成嵌套；要展平用 extend。
  • ys = xs 是共享不是拷贝：改 ys 会波及 xs（例2 的 alias）。拷贝用 xs[:] 或 list(xs)。
  • [[]] * 3 是三个同一个空列表：乘号只复制元素的引用，可变对象（list/dict）别用乘法造「一排」；要三份独立的用 [[] for _ in range(3)]。这和 0004 的可变默认值是同一个家族——共享可变对象。
  • remove / index 找不到会抛 ValueError：Java 的 List.indexOf 找不到返 -1，Python 直接异常，删人/查找前先 in 判断。
  • 解包数量对不上：a, b, c = (1, 2) 抛 ValueError。需要「收走剩下」用 a, *rest = ...。
  • 一元组掉逗号：("only") 是 str；("only", ) 才是 tuple。
  • 和 Java 易混：subList 是视图、切片是拷贝；Python list 允许异构元素但别混用；sort 是原地、sorted 是新 list，两条都得记。
