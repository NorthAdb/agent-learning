系统讲解

1. 类是图纸，实例是造出来的对象

类（class）：一类对象的模板（有哪些数据、能接收哪些消息）。 实例（instance）：按模板在内存里造出来的那一个具体对象。 同一张图纸可以造很多个实例，彼此数据独立。

0004 用函数 + dict 描述一次会话；当「用户名 + 已走轮数」要绑在一起到处传时，用对象更干净：

class Session:
    def __init__(self, user: str) -> None:
        self.user = user
        self.turns = 0

    def note(self, text: str) -> str:
        self.turns += 1
        return f"{self.user}#{self.turns}: {text}"

a = Session("alice")   # 造实例；没有 new
b = Session("bob")
a.note("search")       # alice 的 turns 变成 1；bob 仍是 0

a is b 为 False：两个对象、两份内存。 c = a 不会克隆，只是同一个地址又多了一个名字（0005 里 ys = xs 同一规则）。

Python 里 list / dict / Path 本身也是类；[]、{} 是造实例的字面量语法。

2. __init__ 和 self

__init__：初始化方法。调用 Session("alice") 时，解释器先分配对象，再自动调用 __init__，把 "alice" 传进去。它不是随便起的名字，两侧各两条下划线。

self：当前这个实例。方法的第一个参数约定叫 self（名字可改，但别改）。 Java 的 this 是隐式的；Python 必须写在形参表里。

写法self 从哪来
a.note("search")点号左边的 a 自动填进第一个参数
Session.note(a, "search")你自己把实例当第一个参数传入（少见，但能说明机制）

两种写法是同一件事。日常只用第一种。

self.user = user：在这个实例上创建一个叫 user 的属性。 左边是对象上的格子，右边是传进来的值。漏写 self. 会变成局部变量，出了 __init__ 就丢。

2.1 名字：哪些是 Python 的，哪些是你起的

先分清两层，后面就不会和 handler 缠在一起：

种类例子能不能改名
Python / 标准库约定的特殊名 __init__、__name__、__slots__、self（约定） __init__ 等改了就失效；self 能改但别改
作者自己起的属性名 user、turns、handler、name、_tools 可以改；全项目一起改引用即可
作者自己起的方法名 note、run、register、dispatch 同上
作者自己起的函数名 run_echo、main 同上

handler 不是 Python 关键字，也不是语言内置属性。 它只是本课 ToolSpec 作者给「存放工具实现函数」那个格子起的名字，和把字段叫 user 一样随意（在合法标识符范围内）。

2.2 一个属性 = 一个格子 = 一份值

属性不是「魔法挂钩」，就是对象上的命名格子。 一次赋值只装一份对象：再赋值会覆盖，不会自动「追加第二个函数」。 

spec.handler = run_echo
spec.handler = run_read   # 覆盖：现在只剩 run_read，echo 丢了

# 若真要「一个名字下挂多个函数」，格子里应放容器，而不是反复写 .handler =：
spec.hooks = [run_a, run_b]          # list：有序多个
registry._tools = {"echo": spec, ...}  # dict：按名字多个（本课注册表就是这种）

所以：不是「任何属性都能绑定多个函数」。 默认一个属性绑一份值；要多个，要么多个属性（on_start / on_end），要么一个属性里放 list/dict。 本课设计是：一个 ToolSpec 只有一个 handler；多个工具 = 多份 ToolSpec，收进 ToolRegistry._tools。

2.3 本课三类对象各自有哪些格子（作者设计）

类作者起的属性名格子里通常放什么
Session user、turns 字符串、整数（普通数据）
ToolSpec name、description、handler、calls str、str、一个函数对象、list
ToolRegistry _tools dict：工具名 → 某份 ToolSpec（从而间接管住多个函数）

方法（note / run / register）写在 class 里，是「对象会干什么」， 和「格子里碰巧存了一个函数」不是同一种写法：前者用 def 定义；后者用赋值 self.handler = run_echo。

2.4 handler 能改名吗？建议改吗？

问题答案
语言允不允许改？ 允许。改成 fn / impl / callback 都行，只要 run 里也改成 self.fn(**arguments)。
本课建议改吗？ 不建议。课件、脚本、检索题都用 handler；改名增加对照成本，没有新知识。
别的项目一定叫 handler 吗？ 不一定。North s02 甚至没有这个属性名——函数直接放在 dict：TOOL_HANDLERS["echo"] = run_echo。

Java 对照：字段名也是你起的；private Function<...> handler 改成 impl 完全合法。 构造用 __init__、入口判断用 __name__ 才是「平台认的名字」。

3. 注册表是什么；为什么要「存函数」

注册表：一张「名字 → 怎么执行」的对照表。模型只吐出字符串名字（如 "echo"）和参数 dict； harness 查表找到对应实现，再真正去跑。没有这张表，loop 就只能写死 if name == "echo": ...，每加一个工具改一处分支。

形态长什么样哪里见过
dict 注册表 TOOLBOX["echo"] = run_echo 0004 tools.py；North s02 TOOL_HANDLERS
对象注册表 registry.register(ToolSpec(..., run_echo)) 本课 tool_registry.py 的 ToolRegistry

两套写法干的是同一件事：按名字找到可调用的东西，再传参执行。

3.1 方法 vs 函数

写在 class 里的 def 叫方法：必须经由某个实例调用（或显式传入实例）。 写在 class 外面的 def 仍是 0004 的函数。North s01 的 run_bash 就是普通函数——工具实现本身常常是普通函数，注册表只是「挂起来」的地方。

3.2 「存函数」到底存的是什么

Python 里函数也是对象：名字 run_echo 指向那份可执行代码。 存函数 = 把这份对象放进表里或属性里，现在不跑；等模型真的点名再跑。 加括号 () 才是调用：立刻执行，得到返回值（常常是 str）。 

def run_echo(text: str) -> str:
    return f"(echo) {text}"

# 注册阶段（准备抽屉）：只要说明书，不要立刻干活
spec.handler = run_echo       # 对：handler 里是函数对象
# spec.handler = run_echo()   # 错：立刻调用；缺 text → TypeError
#                             # 即便写成 run_echo("x")，存进去的也是 str，不是函数

# 调度阶段（模型已经给出 arguments）：这时才调用
result = spec.handler(**{"text": "pwd"})   # 等价 run_echo(text="pwd")

时间线拆开看就清楚：

时刻你写什么表里 / 属性里实际是什么
注册handler = run_echo（无括号）函数对象，以后还能再调
误写成调用handler = run_echo()要么立刻报错，要么存成返回值 str
dispatchhandler(**arguments)（有括号 / **）这时才执行，得到工具输出

这和 0004 的 TOOLBOX["rag_search"] = rag_search 完全一样； 本课只是把「函数」挂到 ToolSpec.handler 属性上，再由 ToolRegistry 按名字保管多份 ToolSpec。

Java 直觉：注册表 ≈ Map<String, Function> 或策略表； run_echo 像方法引用，run_echo() 像立刻 invoke。注册时放引用，调度时才 invoke。

3.3 谁进表；合拍约定（呼应 2.1–2.4）

不是每个函数都要 .handler = ...——只有准备给模型按名字调用的工具实现才进表 （run_echo / run_read）。main、build_demo_registry 等直接调用即可。 

# 进表
registry.register(ToolSpec("echo", "...", run_echo))

# 不进表
def main() -> None: ...

赋值很宽松，几乎什么都能塞进 handler；合不合用看 run 怎么调： return self.handler(**arguments)。因此要同时满足：

约定含义反例
可调用 后面能加 (**...) handler = "echo"
参数对得上 关键字名对上模型 dict 的键 形参叫 text，却传入 {"command": ...}
返回观察文本 本课约定返回 str print（返回 None）

Callable[..., str] 是文档约定，运行时默认不拦（0009）。 字段名叫 handler 只是本课起名（见 2.4）；一个格子只装一个函数（见 2.2）。

handler 不是仪式：North s02 用 TOOL_HANDLERS["echo"] = run_echo，没有 .handler 属性，意思相同。

4. 可变状态三案（必背）

列表一旦共享，一次 append 会污染别人。三种写法结果不同——examples.py 例 3 可跑对照：

写法list 何时创建两个实例互不影响？
① def __init__ 里 self.calls = []每个实例构造时新建隔离
② 写在 class 体上的 calls = []定义类时创建一份串了（近似 Java static 字段）
③ def __init__(self, calls=[])定义函数时创建一份（0004 同一条）串了
① Isolated：每个 __init__ 里 self.calls = []
② SharedOnClass.calls = []     # 所有实例 self.calls 指向同一 list
③ SharedDefault(calls=[])      # 没传入时反复用定义时那个 list

独立会话用 ①。同一场对话要累加，把同一份 list 显式传入，不要靠 ②③ 偷懒。 dataclass 里对应 ① 的写法见讲解 6.1 的 field(default_factory=list)。

5. 继承：自定义异常

继承：在已有类上造新类，获得父类的能力再加自己的。语法：class 子类(父类):。 没写括号时，默认父类是 object。

读 Agent 代码最常见的继承，是自定义异常——0010 已经写过：

class UnknownToolError(Exception):
    """工具名不在表里。"""

raise UnknownToolError("unknown tool: glob")
# isinstance(error, Exception) 为 True，所以 except Exception 也能抓住它

子类可以当父类用（loop 仍 except Exception）；专门 except UnknownToolError 时语义更清楚。 Day19 的 Person/Student 长例、多重继承、方法重写深挖本课不做。

6. @dataclass：装饰器只认这一颗糖

装饰器：用一个函数去加工另一个函数或类。语法糖是把 @名字 写在定义上一行。 @dataclass 写在 class ToolSpec: 上方，等价于事后执行 ToolSpec = dataclass(ToolSpec)。 加工结果：按标注好的字段自动生成 __init__、repr 等。你不必手写 self.name = name。 

from dataclasses import dataclass, field

@dataclass
class ToolSpec:
    name: str                      # 模型点名用的字符串
    description: str               # 给模型看的说明
    handler: Callable[..., str]    # 真正执行的函数（见讲解 3.3）
    calls: list[str] = field(default_factory=list)  # 本实例调用记录

# 上面四行 = 作者设计的属性清单（不是 Python 强制的）
# 自动得到：
# ToolSpec("echo", "…", run_echo)  这种 __init__
# print(spec)  能看见字段，而不是 <ToolSpec object at 0x…>

North s12 的 @dataclass class Task: 就是这种：一堆字段 + 自动构造——字段同样是那一章作者按任务系统需要选的，不是语言自带的。 本课不要求自己写装饰器函数（Day17）；见到任意 @foo 先读成「下一行的定义被 foo 加工过」。

6.1 field / default_factory：不是关键字，从哪来

很多同学在这里卡住：default_factory 不是 Python 关键字，也和 handler 一样不是语言内置属性名。 它来自标准库，要先 from dataclasses import field，再写在字段默认值的位置。

片段是什么
fielddataclasses 模块里的函数，用来给某个字段加规则
default_factory传给 field() 的参数名（库作者起的）
= list传函数对象 list（无括号），表示「需要默认值时调用它造新对象」
from dataclasses import dataclass, field

@dataclass
class ToolSpec:
    # 危险：看起来像 ①，其实是 ③——定义 class 时那一个 [] 被所有实例共用
    # calls: list[str] = []

    # 安全：对应三案 ①——每次 ToolSpec(...) 时执行 list()，得到新空列表
    calls: list[str] = field(default_factory=list)

    # 错：default_factory=list() 在定义 class 时就建了一个 list，又变共用
    # calls: list[str] = field(default_factory=list())

和手写 class 的对应关系：

目标普通 classdataclass
三案 ① 每实例一份 listdef __init__(self): self.calls = []field(default_factory=list)
三案 ③ 共用默认 listdef __init__(self, calls=[])calls: list = []（同样危险）

为什么 dataclass 不能简单写 = []？因为它自动生成 __init__，字段上的 = [] 会掉进和 0004「默认值只求值一次」同一条坑（讲解 4）。 field(default_factory=list) 就是官方给的安全写法：把「每次构造时 list()」写进字段声明里。

跑 examples.py 例 5 可对照：两个 ToolSpec 实例的 calls 互不影响；若改成 = [] 会串。

6.2 Callable[..., str]：本课首次出现（衔接 0004 + 0009）

0009 见过 list[str]、-> str；0004 见过把函数存进注册表。 本课第一次把两者合在一起：用 Callable[..., str] 标注「这个格子里应存函数」。

课你已会本课新增
0004TOOLBOX["echo"] = run_echo（存函数对象）—
0009name: str、-> str（标注给人看）—

6.2.1 拆开读
from collections.abc import Callable   # abc = Abstract Base Classes，不是字母表

handler: Callable[..., str]
#       ↑        ↑    ↑
#       │        │    └── 标注：调用后应返回 str（本课工具观察文本）
#       │        └── ... = 省略号：参数形状在类型里先不写死
#       └── 标注：这里应是「可调用」对象

若只描述 run_echo 一种工具，可以写得更死： Callable[[str], str]（一个 str 位置参数，返回 str）。 注册表要兼容 echo / read 等不同 keyword，所以在类型里用 ... 占位；运行时仍靠 self.handler(**arguments) 对上形参，键不对会 TypeError。

# 对的理解：传给 self.handler 里存着的 run_echo

# 若 handler 是 run_echo，arguments 是 {"text": "pwd"}

6.3 构造 ToolSpec：传几个参数

先分清两件事：类上有 4 个字段；这一行调用 只传了 3 个实参。 第 4 个字段 calls 写了 field(default_factory=list)，所以可以不传，解释器自动建空 list。 

ToolSpec("echo", "Echo a string; fake bash.", run_echo)
#        ↑ 1      ↑ 2                            ↑ 3
#        name     description                    handler（无括号）
# 第 4 个字段 calls：本行没写 → 自动 list() 得到 []

# 若真要手填第 4 个（一般不需要）：
# ToolSpec("echo", "说明", run_echo, ["already"])
# 或 ToolSpec(name="echo", description="说明", handler=run_echo, calls=["already"])
字段（共 4）本行有没有传结果
name传了 "echo"必填
description传了说明字符串必填
handler传了 run_echo必填
calls没传用默认 → 新 []

检索题「传了几个」指的是括号里写了几个实参（3）；「加一个默认」指类上还有第 4 个字段可省略。不是括号里写了四个值。

也可全用关键字，顺序无关：

  2. @dataclass class ToolSpec：四个字段；构造常传 3 个（讲解 6.3）。 handler: Callable[..., str] 是 0009 标注 + 0004 函数对象（讲解 6.2）； calls 用 field(default_factory=list) 走三案 ①。
  3. schema / run：对外接口。 run 里 self.handler(**arguments) 就是 0004 的 dict 展开。
  4. ToolRegistry：讲解 3 的「对象注册表」。手写 class（没有 dataclass），因为要藏一个 _tools: dict[str, ToolSpec]，并提供 register / dispatch。 下划线前缀 _tools 是「请把我当内部实现」的约定，不是强制私有（Day19 双下划线本课不展开）。
  5. register：把一份 ToolSpec（含函数对象 handler）按 name 放进表。注意构造时写 run_echo 无括号——这就是「存函数」。
  6. dispatch：查表 → 没有就 raise UnknownToolError → 有就 spec.run(**arguments) → 内部再 self.handler(**arguments)。 North s02 的 TOOL_HANDLERS[name](**input) 是同一句话的 dict 版。
  7. main：注册 echo / read 两个假工具（不调真 shell）。看 echo.calls 与 read.calls 互不污染；看 dataclass 的 repr。

常见坑 + 边界

  • 忘了 self：def note(text): 会在 a.note("x") 时把实例塞进 text，立刻对不上。
  • 漏 self.：user = user 在 __init__ 里是局部变量，实例上没有 .user。
  • 写成 new Session()：SyntaxError 或 NameError。Python 没有 new。
  • 三案 ②③ / dataclass 写 = []：可变默认值只求值一次。dataclass 要用 field(default_factory=list)（讲解 6.1），不是关键字。
  • default_factory=list()：定义 class 时就建 list，又变共用；要传 list 函数本身。
  • 注册时 handler() 多写了括号：立刻调用；缺参会 TypeError；有参则把 str 存进表，dispatch 再 (**args) 时变成「对字符串当函数调」。
  • 把注册表当成「已经跑完的结果表」：表里应是可调用对象；结果是 dispatch 之后 才有的。
  • 以为 class 自带固定属性清单：user/handler 都是作者起名；Python 认的是 __init__ 这类特殊名（讲解 2.1）。
  • 以为一个属性能自动绑多个函数：一次赋值一份值，再赋就覆盖；多个要用 list/dict 或多种 ToolSpec（讲解 2.2）。
  • 以为任意函数都要 .handler =：只有进注册表的工具实现才挂；合拍约定见讲解 3.3。
  • 以为 handler 里存的是 Callable：存的是 run_echo 等函数；Callable[..., str] 只是标注（讲解 6.2）。
  • 以为 Callable[..., str] 表示「只要返回 str 任意函数都行」：参数仍要对上 **arguments；标注默认不拦运行时。
  • 以为标注会拦错类型：0009 仍成立。Session(1) 运行时不会因为 user: str 而拒绝。
  • 和 Java 易混：实例字段通常不在类顶声明；类顶的赋值更像 static。构造函数不叫类名，叫 __init__。
