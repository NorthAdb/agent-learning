系统讲解

1. 线程：主 loop 不等慢命令

1.1 它是什么？

线程（thread）：同一进程里另一条执行线。 默认你写的代码只在主线程里从上到下跑； Thread(...).start() 再开一条线，可以和主线程并行干活。

本课说的「并行」是「主线程不必干等后台结束」——足够读懂 North s13。 不展开 GIL / CPU 密集等进阶话题。

1.2 解决什么问题？

s13：有的 bash 可能超过几十秒。若在主 loop 里同步 subprocess.run 死等， 模型没法继续规划、用户也像卡住。 做法：把慢活丢进后台线程，主 loop 立刻返回「已派发」，稍后查结果表。

1.3 拆开读：创建线程那一行

import threading
import time

def worker(task_id: str, delay: float) -> None:
    time.sleep(delay)
    print(task_id, "done")

t = threading.Thread(target=worker, args=("bg_1", 0.15), daemon=True)
t.start()          # 立刻返回，不等 worker 结束
print("主线程继续") # 此时 worker 可能还在 sleep
t.join(timeout=2)  # 可选：最多等 2 秒再往下
片段含义
threading.Thread(...) 造一个线程对象；此时还没跑 worker
target=worker 后台要执行的函数对象（0004：函数名不带括号 = 对象本身）
args=("bg_1", 0.15) 传给 worker 的位置参数（按顺序对上函数形参，不靠名字）： 第 1 个 → task_id，第 2 个 → delay。 必须是元组
daemon=True 守护线程：主程序结束时，这类线程会被直接丢掉
t.start() 真正启动；立即返回，不等 worker 跑完
t.join(timeout=2) 主线程在这里等：worker 结束，或最多等 2 秒

1.4 关键参数与三案

点含义坑
target=worker 函数对象 target=worker() 会先在主线程跑完，后台啥也没有
args=(...) 位置参数元组 单元素别忘逗号：("bg_1",)；写成 ("bg_1") 只是字符串
daemon=True 主退出即丢 不保证退出前把活干完；Agent 进程常驻时通常够用
start() 启动并立即返回 不要以为 start 会等到结束
join(timeout=...) 可选：等它结束（或等到超时） 教学/脚本里用来「等结果出现」；s13 主 loop 通常不 join，而是查结果表

target 三案（必背）：

案写法结果
① 正确 Thread(target=worker, args=("bg_1",)) 后台线程里调用 worker("bg_1") ✅
② 多了括号 Thread(target=worker()) 主线程立刻跑完 worker，target 收到的往往是 None ❌
③ 传了字符串 Thread(target="worker") 字符串不可调用 → 启动时报错 ❌

时间线直觉：start() 之后主线程和 worker 同时往前走； 若马上 print(results)，往往还是空的——worker 还在 sleep。 要「等结果」，用 join，或像主脚本那样稍后再查共享表。

2. 锁：共享 dict 的安全带

2.1 它是什么？解决什么？

两个线程同时改同一个 dict：可能一个读到一半、另一个改完了， 甚至损坏 dict 内部结构（偶发、难复现的 bug）。

Lock（锁）：同一时刻只让一个线程进入 with lock: 包住的那段代码（叫临界区）。 别的线程要进同一把锁，必须等当前线程退出 with。 

lock = threading.Lock()
results: dict[str, str] = {}

def worker(task_id: str, delay: float) -> None:
    time.sleep(delay)          # 睡在锁外！别堵住别人
    with lock:
        results[task_id] = f"done after {delay}s"  # 读改共享状态放里面

with lock: 进入时抢锁，离开时（含异常）自动放锁—— 比手写 lock.acquire() / lock.release() 更不容易漏放。

2.2 锁内 vs 锁外（拆开主脚本）

放哪例子为什么
锁外 time.sleep(delay)、跑 bash、调网络 慢活占着锁 → 别的线程全堵死
锁内 读/写 jobs / results、改 status 共享状态的读和写要成一组，避免半截状态

s13 / 本课主脚本：sleep 在锁外；改 jobs[job_id] 在锁内。

2.3 三案

案情况做法
①只读、无线程共享不必加锁
②多线程读写同一 dictwith lock: 包住相关读和写
③锁里再调可能抢同一把锁的函数死锁风险；临界区短、别嵌套同一把锁

本课锁是不可重入的普通 Lock（同一线程也不能二次 acquire 同一把）。 North s13 用的也是这种；见到 RLock 再说。

3. datetime：现在几点、过了多久

3.1 它是什么？

datetime 是标准库模块，处理日期和时间。 常见导入：from datetime import datetime, timedelta （注意：模块名和类名都叫 datetime，所以常常「from 模块 import 类」）。

本课认四个动作：

写法做什么得到什么
datetime.now() 取本地「现在」 datetime 对象（有年/月/日/时/分/秒…）
timedelta(minutes=1) 表示一段时间长度 可与 now 做加减：now + timedelta(...)
now.strftime("%Y-%m-%d %H:%M:%S") 按你指定的格式变成字符串 适合打印、日志
now.isoformat(timespec="seconds") 按 ISO 标准格式变成字符串 适合进 JSON / 落盘（主脚本 started_at） 
from datetime import datetime, timedelta

now = datetime.now()
now.strftime("%Y-%m-%d %H:%M:%S")           # 如 2026-08-31 11:05:03
(now + timedelta(minutes=1)).strftime("%H:%M:%S")
now.isoformat(timespec="seconds")           # 如 2026-08-31T11:05:03

3.2 strftime vs isoformat

strftimeisoformat
格式谁定 你用 %Y %m 等自己拼 标准 ISO 8601（中间有 T）
常见用途 给人看的日志 给程序存的字段（JSON）
本课主脚本 例 2 演示打印 Job.started_at 用 isoformat

timespec="seconds"：精度到秒，不要毫秒尾巴——字段更干净。

3.3 解决什么问题？

s14 cron：用 datetime.now() 判断「这一分钟该不该触发」。 后台任务也要记录 started_at，方便以后排查「几点派发的」。 本课不实现 cron 五段表达式，只认取时、做差、变成字符串。

4. asdict：dataclass → 可 JSON 的 dict

4.1 它是什么？解决什么？

0012 的 @dataclass 实例是自定义对象， 不能直接 json.dumps(task)（0008 的 dumps 只认 dict / list / 数字 / 字符串 / bool / None）。

from dataclasses import asdict 后， asdict(task) 把实例变成普通 dict（键是字段名，值是字段值），再 dumps。 s12 save_task 就是这一句。 

from dataclasses import asdict, dataclass
import json

@dataclass
class Task:
    id: str
    status: str
    owner: str | None = None

task = Task("task_1", "pending")
d = asdict(task)
# → {"id": "task_1", "status": "pending", "owner": None}

json.dumps(d)          # ✅
# json.dumps(task)     # ❌ TypeError：不是 JSON 原生类型

4.2 和主脚本怎么接

snapshot() 在锁内对每个 Job 做 asdict， 得到 list[dict]——外面可以安心打印或以后 dumps， 且遍历时不会和 worker 改表打架。

5. global：函数里改模块级名字

5.1 它是什么？

写在 .py 文件顶层的变量（如 _counter = 0）叫模块级变量。 函数里若只是读取它，或只改它指向的对象内部（list.append、dict[k]=）， 一般不用声明。

但若函数里要给这个名字重新赋值（_counter = ... 或 _counter += 1）， Python 会默认当成「函数局部变量」。要改外面那个模块级名，必须写： 

def _next_id() -> str:
    global _counter   # 声明：下面的 _counter 指模块级那个
    _counter += 1
    return f"bg_{_counter:04d}"

5.2 三案（必背）

案函数里做什么要不要 global
① 重新赋值 _counter += 1 / _counter = 5 要 global _counter
② 只读 print(_counter) / return _counter 不必
③ 改对象内部 jobs[id] = ... / lst.append(...) 不必（名字还是指向同一个 dict/list）

s13 global _bg_counter 同款。 和实例属性 self.x 不是一回事：类方法里改 self.x 从不写 global。

常见坑 + 边界

  • Thread(target=worker())：多了括号，立刻在主线程跑完。
  • args=("bg_1")：少了逗号，不是单元素元组。
  • 不加锁改共享 dict：数据损坏 / 偶发诡异 bug。
  • 在锁里做网络 / 长时间 sleep：堵住别的线程；慢活放锁外。
  • 以为 daemon 会在退出前干完：不会，主进程走了它就丢。
  • 直接 json.dumps(dataclass实例)：先 asdict。
  • 函数里 _counter += 1 忘了 global：UnboundLocalError 或改错成局部变量。
  • 把线程当成 async：North 全程同步 + 线程；本课不引入 await。
