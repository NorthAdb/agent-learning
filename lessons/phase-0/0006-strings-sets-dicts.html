系统讲解

1. 字符串是不可变的有序序列

字符串支持列表熟悉的 len、索引、切片、in，但不能通过索引修改字符。任何“修改”都会创建新字符串。

query = "harness"
query[0]          # 'h'
query[-1]         # 's'
query[1:4]        # 'arn'
"ness" in query   # True
# query[0] = "H"  # TypeError: str 不可变
query = "H" + query[1:]  # 重新绑定到一个新字符串

这和 Java String 的核心直觉一致。原始字符串 r"C:\\new" 适合 Windows 路径或正则模式；普通字符串里的 \n、\t 会被解释成换行和制表符。

2. 清洗：strip、replace、大小写与判断

raw = "  RAG：先检索，再生成。  "
clean = raw.strip().replace("：", ":")
print(repr(clean))          # 'RAG:先检索，再生成。'
print(clean.lower())         # 英文大小写归一化
print(clean.startswith("RAG"))
print("query".isalnum())     # True，全部字符都是字母
print(clean.find("RAG"))      # 找不到返回 -1
print(clean.index("RAG"))     # 找不到会抛 ValueError

startswith(prefix) 返回布尔值，判断字符串是否以指定前缀开头；对应的 endswith(suffix) 判断结尾。它们不会修改原字符串，也可以接收元组来一次检查多个候选：

name = "rag_search"
name.startswith("rag_")             # True
name.startswith(("rag_", "read_"))  # True，命中任意一个前缀
name.endswith(("_search", "_file")) # True

isalnum() 是“is alphanumeric”的缩写：只有当字符串非空且每个字符都是字母或数字时才返回 True。空字符串、空格、下划线、连字符、中文标点都会让它返回 False；中文汉字本身属于 Unicode 字母，因此 "知识".isalnum() 会是 True。

"query".isalnum()       # True
"query2".isalnum()      # True
"query_2".isalnum()     # False，下划线不是字母或数字
"".isalnum()            # False，空字符串不算
"知识".isalnum()         # True，汉字属于 Unicode 字母
"RAG: docs".isalnum()   # False，含冒号和空格

在 Agent 代码里，startswith 适合做轻量路由（例如判断工具名是否属于 rag_ 命名空间）；isalnum 适合做简单标识符检查，但不能替代完整协议校验——真实的工具名通常允许下划线，所以应使用白名单或更明确的规则。strip 默认去两端空白，也可以传字符集合，如 "~hi~".strip("~")。find 和 index 的失败行为不同：用户输入搜索通常用 find，协议字段必须存在时才考虑直接索引或显式抛错。

3. split、splitlines、join：RAG 文本的三步

先记输入输出：str.split 和 str.splitlines 都是“一个字符串 → 一个列表”；join 是“一个分隔符 + 一个字符串列表 → 一个字符串”。它们不是三个相似方法，而是文本管线中相反方向的两个动作。

写法做什么典型结果RAG 用途
text.split(",")按指定分隔符切"a,b" → ["a", "b"]CSV、标签、协议字段
text.split()按任意连续空白切，自动丢两端空白" a b " → ["a", "b"]压缩 query 中的多余空格
text.splitlines()按换行边界切，不保留换行符"a\\n\\nb" → ["a", "", "b"]逐行清洗、保留空行语义
"\\n".join(lines)用换行把多条字符串合成一段["a", "b"] → "a\\nb"生成上下文块或 prompt

为什么不总用 split("\\n")？splitlines() 对不同换行风格（\\n、\\r\\n）更稳，而且语义就是“按行拆”。如果你需要保留空行，就不要立刻写 if line.strip()；如果空行只是噪声，才过滤它。

text = "标题\n\n第一段。\r\n第二段。"
print(text.split("\n"))       # 可能留下 '\r'，不适合作为跨平台按行处理
print(text.splitlines())       # ['标题', '', '第一段。', '第二段。']

raw_lines = text.splitlines()
kept_lines = [line.strip() for line in raw_lines if line.strip()]
print(kept_lines)              # ['标题', '第一段。', '第二段。']

这就是之前那条列表生成式的完整语义：先拆行，再逐行清洗；if line.strip() 过滤清洗后为空的行；前面的 line.strip() 把保留下来的行变干净。等价的普通循环是：

lines = []
for line in text.splitlines():
    cleaned = line.strip()
    if cleaned:
        lines.append(cleaned)

RAG 中常见的第一版组装：

numbered = [f"[{i}] {line}" for i, line in enumerate(kept_lines, start=1)]
context = "\n".join(numbered)
print(context)
# [1] 标题
# [2] 第一段。
# [3] 第二段。

编号不是装饰：它让模型回答时可以引用来源，也让调试时能知道哪一块进入了 prompt。换行符是“块与块之间的边界”；如果需要更强的视觉分隔，可以用 "\n\n".join(blocks)，但要意识到这会增加 prompt token。

3.1 split 的两个重要边界

不传分隔符和传空格分隔符不是一回事：

query = "  Java   Agent  "
query.split()       # ['Java', 'Agent']：连续空白合并，首尾空白丢弃
query.split(" ")    # ['', '', 'Java', '', '', 'Agent', '', '']：每个字面空格都参与切分

清洗用户 query 时通常用 split() 再 join 回单空格：

normalized = " ".join(query.split())
print(normalized)    # Java Agent

maxsplit 用于“只拆前几刀，剩余内容原样保留”。例如工具协议中，冒号前是动作名，后面可能仍有冒号：

wire = "tool:read_file:C:\\docs\\agent.txt"
head, body = wire.split(":", 1)
print(head)          # tool
print(body)          # read_file:C:\\docs\\agent.txt

如果写成不带 1 的 split(":")，就会得到 4 段，调用方还要猜哪几段属于 body；协议解析通常应明确限制切分次数。

3.2 从“按行”到“按段落”：更像 RAG 的 chunk

逐行不是唯一切法。知识库通常希望一个 chunk 保留完整小段，而不是把一句话和下一句拆散。可以先按空行切段，再清洗每段：

document = "标题\n\n第一段的第一句。\n第一段的第二句。\n\n第二段。"
paragraphs = [
    " ".join(block.split())
    for block in document.split("\n\n")
    if block.strip()
]
print(paragraphs)
# ['标题', '第一段的第一句。 第一段的第二句。', '第二段。']

这里有两层处理：

  1. document.split("\n\n") 按空行保留段落边界。
  2. " ".join(block.split()) 把段落内部的换行、多个空格压成单空格，但不把不同段落混在一起。

这仍然是“最小 chunker”，不等于生产级分块：真实系统还要考虑最大 token 数、重叠窗口、标题继承和代码块保护。但它已经展示了 RAG 中一个关键设计：分隔符选择会改变检索单元的语义。

3.3 join 的边界：类型、空列表和嵌套列表

" | ".join(["rag", "tool"])  # 'rag | tool'
" | ".join([])               # ''，空列表得到空字符串
# " | ".join(["rag", 3])     # TypeError，3 不是 str
" | ".join(map(str, ["rag", 3]))  # 'rag | 3'

join 不会递归处理嵌套列表；如果候选结果是 list[dict]，要先取出每个 dict 的文本字段，再 join：

hits = [{"text": "Tool 是动作"}, {"text": "RAG 先检索"}]
context = "\n".join(hit["text"] for hit in hits)
print(context)

这个生成器表达式避免先额外创建一个文本列表；在小数据上两者都可以，读代码时先关注“每个 hit 取 text，再用换行合并”的数据流。

3.4 反向理解：为什么 prompt 组装要可观察

不要直接写一行不可读的字符串拼接。把 blocks、numbered、context 分开，才能在日志中检查：哪些候选进入了上下文、空块是否被过滤、编号是否稳定、最终长度是否超限。一个可读的组装函数：

def build_context(snippets: list[str], max_blocks: int = 3) -> str:
    blocks = [s.strip() for s in snippets if s.strip()]
    blocks = blocks[:max_blocks]
    numbered = [f"[{i}] {block}" for i, block in enumerate(blocks, 1)]
    return "\n\n".join(numbered) or "（无相关资料）"

这段函数把 0005 的列表截断、0006 的字符串清洗与合并串起来了：先过滤空块，再限制数量，最后组装；空结果有明确占位。它就是从“会用 API”走向“能写 RAG 处理代码”的一步。

split、splitlines、join 的共同点是都不修改原字符串；它们返回新对象。这个不可变性规则仍然有效。

4. f-string：把结构化值写进 prompt

tool = "rag_search"
top_k = 3
score = 0.9173
message = f"tool={tool} top_k={top_k} score={score:.2f}"
prompt = f"请依据资料回答：\n{context}\n\n问题：{clean}"
print(message)
print(prompt)

f-string 的花括号里可以放表达式，格式说明写在冒号后。不要把用户输入直接当作 f-string 模板执行；模板是代码，用户内容只是值。

5. 字符串方法不会改变原值

name = "  Alice  "
name.strip()
print(repr(name))            # 仍是 '  Alice  '
name = name.strip()          # 想保留结果，必须接回
name = name.replace("Alice", "Bob")

这是 0004 可变默认值、0005 列表原地方法之后的另一组边界：列表有 sort() 这种原地方法，字符串没有原地修改；字符串方法几乎都返回新值。

6. 集合：表达“唯一成员”和集合关系

seen = {"rag", "tool", "rag", "memory"}
requested = {"rag", "eval", "tool"}
print(seen)                  # 重复 rag 只保留一份，顺序不承诺
print("rag" in seen)         # 成员判断
print(seen & requested)       # 交集：两边都有
print(requested - seen)       # 差集：请求但尚未具备
print(seen | requested)       # 并集：合并
print(seen ^ requested)       # 对称差：只在一边出现

set() 才是空集合，{} 是空字典。集合元素必须可哈希："rag"、整数、元组通常可以；list、dict、set 不可以。集合适合“有没有”，不适合“第几个”。

ids = ["d-01", "d-01", "d-03"]
unique_ids = set(ids)         # 去重
stable_ids = sorted(unique_ids) # 需要展示/测试稳定时再排序

7. 集合的增删与生成式

tools = {"read_file"}
tools.add("rag_search")
tools.update({"final", "read_file"}) # 重复添加没有效果
tools.discard("missing")             # 不存在也不抛异常
tools.remove("final")                 # 不存在会抛 KeyError

numeric = {n * n for n in range(6) if n % 2 == 0}
print(numeric)                        # {0, 4, 16}

不知道元素是否存在时，discard 比 remove 更宽容；协议校验需要强制发现错误时才用 remove 或显式判断。

8. 字典：tool call 的外形

call = {
    "name": "rag_search",
    "arguments": {"query": "permission", "top_k": "3"},
}

    name = call["name"]                 # 必填协议字段
    args = call.get("arguments", {})    # 可选字段给默认空 dict
    query = args.get("query", "")
    top_k = int(args.get("top_k", 3))   # 外部 JSON 可能给字符串 "3"
    print(name, query, top_k)

逐行读它：

  1. call 是外层 dict。它有两个键：name 的值是字符串，arguments 的值又是一个 dict。
  2. name = call["name"] 取必填字段。协议规定没有工具名就无法执行，所以缺失时让 KeyError 暴露出来，比悄悄使用一个假工具名更安全。
  3. args = call.get("arguments", {}) 取可选字段。如果调用没有参数，得到一个新的空 dict，后面仍可以调用 args.get(...)。
  4. query = args.get("query", "") 取可选 query。缺失时用空字符串；这表示“当前代码允许没有 query”，并不代表所有工具协议都应该允许它。
  5. top_k = int(args.get("top_k", 3)) 先取值，再转成整数。这里输入可能是 JSON 风格的字符串 "3"，但列表切片需要整数，所以在边界处归一化。
  6. print 输出的是 rag_search permission 3；最后一个 3 的类型是 int，不是字符串。
# 这段数据的形状可以画成：
call                      # dict
├── "name"       -> "rag_search"       # str
└── "arguments"  -> args                # dict
    ├── "query"  -> "permission"       # str
    └── "top_k"  -> "3"                 # str，转换后才是 int 3

必填与可选的选择规则可以这样记：

call["name"]                    # 缺失就是协议错误：抛 KeyError
call.get("arguments", {})       # 缺失可以按“无参数”处理
args.get("top_k", 3)             # 缺失使用业务默认值
int(args.get("top_k", 3))        # 外部类型转换成内部稳定类型

如果输入不可信，实际执行前还要处理转换失败：

raw_top_k = args.get("top_k", 3)
try:
    top_k = int(raw_top_k)
except (TypeError, ValueError):
    raise ValueError(f"top_k must be an integer, got {raw_top_k!r}")

这和 Java 后端接收 JSON DTO 的思路相同：先在边界层解析、校验、转换，再把类型稳定的对象交给业务层。字典键必须是可哈希对象，通常用字符串。d[k] = v 既能新增也能覆盖；del d[k] 删除必存在键；pop(k, default) 可取出并删除。读代码时先判断每个字段是必填还是可选，再选择 [] 或 get。

9. items、keys、values 与嵌套访问

字典保存的是键 → 值的映射。遍历时，先问自己“我需要哪一侧”：只要键用 keys()，只要值用 values()，两侧都要用 items()。

counts = {"tool": 3, "model": 1, "error": 1}

print(counts.keys())    # dict_keys(['tool', 'model', 'error'])
print(counts.values())  # dict_values([3, 1, 1])
print(counts.items())   # dict_items([('tool', 3), ('model', 1), ('error', 1)])

这三个方法返回的是“字典视图”对象，不是普通 list。它们可以直接遍历；如果确实需要列表，再显式写 list(counts.items())。items() 的每个元素是一个二元组 (key, value)，所以 for kind, count in ... 是元组解包：

for kind, count in counts.items():
    print(f"事件 {kind} 出现 {count} 次")

for kind in counts.keys():
    print("只关心名字:", kind)

for count in counts.values():
    print("只关心次数:", count)

不要把 items 当成“字典的一个字段”；它是一个方法，必须写括号。下面两句含义不同：

counts.items      # 方法对象，还没有执行
counts.items()    # 调用方法，得到可遍历的 (key, value) 视图

有了 items()，字典生成式就很好读：

hot = {kind: count for kind, count in counts.items() if count >= 2}
print(hot)                         # {'tool': 3}

它的普通循环等价写法是：

hot = {}
for kind, count in counts.items():
    if count >= 2:
        hot[kind] = count

嵌套访问则是“每一层容器做一次访问”。下面的 call 是外层 dict，arguments 的值是内层 dict：

call = {
    "name": "rag_search",
    "arguments": {"query": "permission", "top_k": "3"},
}

arguments = call["arguments"]       # 第 1 层：外层 dict 取出内层 dict
query = arguments["query"]          # 第 2 层：内层 dict 取出 query

# 一行写法等价于上面两步：
query_again = call["arguments"]["query"]

读嵌套表达式时不要跳步：先确认 call["arguments"] 的类型是 dict，再继续取 ["query"]。如果中间某层缺失，直接索引会抛 KeyError；可选结构可以分层使用 get：

arguments = call.get("arguments", {})
query = arguments.get("query", "")
top_k = int(arguments.get("top_k", 3))

在 tool call 代码里，items() 常用于记录参数、筛选字段或遍历多条配置；keys() 常用于检查是否包含某个字段；values() 常用于统计或判断所有值。生产代码通常先在边界函数中校验嵌套结构，再把稳定数据交给执行层。

10. get、setdefault、pop：三个相近但不同的动作

d = {"name": "rag_search"}
print(d.get("timeout", 10))       # 只读：缺失时返回 10，d 不变
d.setdefault("headers", {})      # 缺失才写入默认值
removed = d.pop("headers")        # 取出并删除
print(removed, d)

get 不写入，setdefault 可能写入，pop 会删除并返回值。三者不能凭名字互换；尤其不要为了“读一下”使用 setdefault，否则会悄悄改变状态。

主脚本导读：parse_tool_call.py

  1. KNOWN_TOOLS 是 set：校验工具名是否在白名单中，避免任意字符串直接进入执行层。

  4. validate_call 先用 get 读取 name 和 arguments，再检查白名单与类型；错误在边界暴露，不让执行函数收到半结构化数据。

常见坑 + 边界

  • 字符串赋值不等于修改：text.strip() 不接回变量，原 text 不变。
  • split / join 方向：text.split() 是 str → list；"sep".join(lines) 是 list[str] → str。
  • join 类型："-".join([1, 2]) 抛 TypeError，先 map(str, values) map(函数, 可迭代对象) 可迭代对象转换为迭代器，然后依次调用函数，返回一个迭代器。
  • find / index：find 找不到返回 -1；index 找不到抛 ValueError。不要把两者当同一个 API。
  • set 无序：不要依赖打印顺序或索引；稳定展示使用 sorted。
  • 空容器：{} 是 dict；空 set 是 set()。
  • dict.get 的 None：d.get("x") 可能得到 None；若 None 本身是合法值，不能用 or default 偷换语义。
  • 外部类型：JSON 的 "3"、"false" 都是字符串；不要只看打印结果，要检查 type 并显式转换。
  • 修改中的遍历：不要在遍历 dict/set 的同时增删元素；先收集待修改项，再统一更新。
