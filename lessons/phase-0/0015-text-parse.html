系统讲解

1. re：正则最小集

1.1 它是什么？

正则表达式（regex）：用符号描述「文本长什么样」。 标准库模块 re 提供搜索/匹配。re.search(pattern, text) 在整段里找第一处； 找到 → Match 对象；找不到 → None（要先判断再 .group）。

和 0014：glob 找文件名；grep 概念是搜文件内容；Python 搜字符串内容用 re（没有 import grep）。

1.2 本课够用的符号

  • \[ \]：匹配字面量方括号（裸 [ 在正则里是「字符类」开头）。
  • (...)：捕获组。group(0) 整段匹配，group(1) 第一对括号里的内容。
  • .*? 非贪婪（尽量短）；.* 贪婪（尽量长）。
  • ^...$：从开头到结尾整串（例：合法名字校验）。

1.3 拆开读：re.search(r"\[(.*?)\]", text)

text = "ids: [req_1, req_2] trailing"
matched = re.search(r"\[(.*?)\]", text)

目标：在整段 text 里找出第一对方括号，并取出括号里面的内容。

片段含义
r"..." 原始字符串：反斜杠按字面交给正则，避免 Python 先吃掉 \
re.search(模式, text) 从左到右找第一处匹配；找到 → Match；找不到 → None
\[ / \] 匹配字面量 [ / ]（裸 [ 在正则里是「字符类」开头，必须转义）
( ... ) 捕获组：把这一段另外记下来，之后用 group(1) 取出
. 任意一个字符（默认不含换行）
* 前面的东西重复 0 次或多次
.*? 任意内容，非贪婪：尽量短，在第一个 ] 就停（不要吃到更后面的 ]）

对上面的 text，眼睛从左扫：

ids: [req_1, req_2] trailing
     ^             ^
     \[   (.*?)    \]
取值结果说明
matched.group(0)[req_1, req_2]整段匹配（含方括号）
matched.group(1)req_1, req_2第一对 () 里捕获的内容

若写成贪婪的 \[.*\]（没有 ?），在「多个 ]」时会尽量吃到最后一个 ]； 本例只有一对括号，两种都能对，但抽模型输出时更常用非贪婪 .*?，或配合 DOTALL 抓整块（见下节）。

顺序口诀：search → 判不是 None → 再 group。

1.4 三案（必背）

案情况结果
①找到（上一小节那例）Match；用 group 取值
②找不到None；对 None 调 group → AttributeError
③re.compile 后再 search/match同一模式复用（见下）

1.5 re.compile 干什么？

re.compile(模式)：把正则字符串先编译成 Pattern 对象，以后反复 compiled.search(text) / compiled.match(text)，不必每次把同一串模式再解析一遍。

写法差别
re.search(r"...", text) 一次性：模式用一次就丢（例 1①② 够用）
pat = re.compile(r"...")
pat.search(text)		 模式要用很多次、或要挂在模块级常量上时更合适 
compiled = re.compile(r"^[A-Za-z0-9._-]{1,16}$")
# ^...$ ：整串必须从头到尾符合（合法短名字）
compiled.match("task_01")   # 有 Match → True
compiled.match("bad name")  # None（有空格）→ False

# 和「每次临时 search」等价，只是模式已备好：
# re.match(r"^[A-Za-z0-9._-]{1,16}$", "task_01")

本课主脚本把跨行方括号模式做成模块常量： TODO_BLOCK = re.compile(r"\[.*\]", re.DOTALL)， 后面只写 TODO_BLOCK.search(text)——编译一次，到处复用。 North s19 的名字校验正则同款思路。

小脚本里偶尔写一次 re.search 完全可以；见到 compile 时读成「先备好模式对象」即可，不是第二种正则语言。

2. re.DOTALL：让 . 能跨行

默认 . 不匹配换行。模型吐的 list 常折行，没有 DOTALL 时 \[.*\] 可能抓不住整块。 s09 写 re.search(r'\[.*\]', text, re.DOTALL)。 

blob = "start[\n  a,\n  b\n]end"
re.search(r"\[.*\]", blob)              # 往往 None（跨不了换行）
re.search(r"\[.*\]", blob, re.DOTALL)   # 能抓住整段方括号

主脚本 TODO_BLOCK = re.compile(r"\[.*\]", re.DOTALL) 就是这一招。

3. 先把 eval 讲清楚，再谈 literal_eval

前序课（0001–0014）没有单独讲过内置函数 eval。 0006 集合练习里的 "eval" 只是工具名字符串，不是这个函数。本课第一次讲。

3.1 eval 是什么？

eval 是 Python内置函数（不用 import）： eval(字符串) 会把这段字符串当成一段 Python 表达式，当场算出来或执行掉。 

# 无害例子：字符串里是普通算术
eval("1 + 2")                    # → 3（int）

# 字符串里也可以是字面量
eval("[1, 2, 3]")                # → [1, 2, 3]（list）
eval("{'a': 1}")                 # → {'a': 1}（dict）

所以 eval 的能力很宽：不只是「读数据」，而是几乎任何合法表达式都能跑—— 包括函数调用、import、属性访问。

3.2 为什么 Agent 课里要禁止对模型输出用 eval？

模型返回的文本不可信：看起来像在给你 todos，里面也可能夹： 

bad = "__import__('os').system('echo hack')"
若写会发生什么
eval(bad) Python 真的去执行：__import__('os') → .system('echo hack') → 在机器上跑命令 ❌
本课练习 / 主脚本 不运行这行；只写在注释里当反面教材。你也不要在解析模型输出时试 eval。

口诀：eval = 把字符串当程序跑。自己写死的 "1+2" 可以演示； 来自模型/用户/网络的字符串 → 禁止 eval。

3.3 ast.literal_eval：只吃字面量（安全替代）

ast.literal_eval(s)（在 import ast 后使用）：同样把字符串变成 Python 对象， 但只允许字面量语法——list / dict / 数字 / 字符串 / True / False / None。 函数调用、import、属性访问 —— 一律拒绝。

解决什么问题：模型给了 [{'id': 1, ...}] 这种带单引号的 Python 风格文本时， 能安全变成 list；又不会像 eval 那样执行 os.system(...)。

eval(s)ast.literal_eval(s)
把字符串当成什么 可执行的 Python 表达式 只能是静态数据（字面量）
"[1, 2]" → list ✅ → list ✅
"__import__('os').system('x')" 会真的执行 ❌ ValueError / SyntaxError，不执行 ✅ 
import ast

ast.literal_eval("[{'id': 1, 'done': False}]")   # → list[dict]（正常数据）

ast.literal_eval("__import__('os').system('x')")
# → 解析阶段就失败；不会真的 system

# eval("__import__('os').system('x')")  # 会执行！模型输出禁止

主脚本流程：先用 re 从乱文本里抽出 [...] 字符串，再 literal_eval 变成 list——全程不用 eval。

常见坑 + 边界

  • 对 None 调 .group：先判断 search 结果。
  • 用 eval 解析模型输出：等于把不可信字符串当程序执行（可跑 os.system 等）；literal_eval 只读字面量，拒绝函数调用。
  • JSON 与 Python 字面量混用：双引号 JSON → json.loads；单引号 dict → literal_eval。
  • 字符类 [A-Za-z] 和字面量 \[：不是一回事。
  • 把 re 和 glob 搞混：re 搜字符串内容；glob 匹配文件名（0014）。
