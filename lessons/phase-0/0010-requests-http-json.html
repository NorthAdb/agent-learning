旁注：DTO 是什么（Java 同学）

DTO = Data Transfer Object（数据传输对象）：专门用来在边界之间搬数据的一类对象，通常对应一份 JSON 的字段形状。

  • Java 里常见样子：一个带字段的类（或 record），如 ChatCompletionResponse，Jackson 把 JSON 直接反序列化成该类；字段名、类型在编译期就钉死，缺字段/类型错常在绑定阶段暴露。
  • 干什么用：在「网络/文件边界」与「业务核心」之间当稳定契约——入参 DTO、出参 DTO，避免业务方法直接啃原始 Map/JsonNode。
  • 和本课的关系：response.json() 只给你 dict/list（松散、无编译期字段表）。若要对齐 Java 的 DTO 习惯，阶段 0 用手动取键 + isinstance（见 0008/0009）；更接近 DTO 的标注是 TypedDict（0009），真正「类 + 校验」常见于后续的 Pydantic 等，本课不展开。
// Java 直觉
ChatCompletionResponse dto = objectMapper.readValue(body, ChatCompletionResponse.class);
String content = dto.getChoices().get(0).getMessage().getContent();

# Python（本课默认）
body = response.json()          # dict，不是 ChatCompletionResponse 类
content = body["choices"][0]["message"]["content"]  # 键写错要到运行时才爆

后文说「不是 DTO」，意思就是：你手里还是普通 dict，没有自动生成的强类型 Java 类。

1. HTTP 请求是什么（Agent 视角）

一次 HTTP 调用 = 你的进程向某个 URL 发消息，对方返回状态码 + 头 + 正文。Agent 里常见形态：

  • GET：查资源（检索、拉配置、健康检查）
  • POST：提交 JSON（chat completions、创建任务、调业务 API）
客户端 (你的 Python)          服务端 (模型 API / RAG / Java)
        |  GET /rag/search?q=...          |
        | -----------------------------> |
        |  200 + {"hits":[...]}           |
        | <----------------------------- |

3. 参数填空手册：requests.get / requests.post

先记住一句：位置参数几乎只有 URL；其它一律用关键字参数（名字=值），这样读代码不会搞混顺序。

3.1 先看完整模板（Agent 里最常见）

# GET：查东西（检索、健康检查）
response = requests.get(
    "http://127.0.0.1:8765/rag/search",   # ① 必填：完整 URL（字符串）
    params={"q": "harness", "top_k": 2}, # ② 可选：拼到 ? 后面的查询参数
    headers={"User-Agent": "agent-learning"},  # ③ 可选：请求头
    timeout=5,                           # ④ 强烈建议：超时秒数
)

# POST：交东西（chat、提交 JSON）
response = requests.post(
    "http://127.0.0.1:8765/v1/chat/completions",  # ① URL
    json={                                        # ② 身体：Python dict → JSON 文本
        "model": "demo-model",
        "messages": [{"role": "user", "content": "什么是 RAG？"}],
    },
    headers={"Authorization": "Bearer YOUR_TOKEN"},  # ③ 可选头
    timeout=5,                                    # ④ 超时
)

对照 Java：有点像 RestTemplate.exchange(url, method, entity, ...)——URL、方法、头、身体、超时是分开设的；requests 把它们收成函数参数。

3.2 每个参数：填什么、类型、放哪

参数名你填什么类型直觉GETPOST说明
第 1 个位置参数

params= 查询参数 dict 常用 少用 变成 URL 上的 ?q=...&top_k=2。值可以是 str/int，requests 会转成字符串并做 URL 编码。

本阶段 Agent 脚本够用的组合就三套：

# A. 健康检查 / 简单 GET
requests.get(url, timeout=5)

# B. 带查询的 GET（RAG 检索）
requests.get(url, params={"q": query, "top_k": 3}, timeout=5)

# C. 提交 JSON 的 POST（chat / 业务 API）
requests.post(url, json=payload, headers=headers, timeout=5)

3.4 逐行拆开本课真实的 post

payload = {
    "model": "demo-model",
    "messages": [{"role": "user", "content": "什么是 RAG？"}],
}
# payload 还是普通 Python dict（0006/0008 的对象）

response = requests.post(
    f"{BASE}/v1/chat/completions",  # BASE="http://127.0.0.1:8765"
    # ↑ f-string 拼出完整 URL；假服务路径模仿 OpenAI 风格

    json=payload,
    # ↑ 关键字参数名必须叫 json（不是 body、不是 payload）
    #   requests 内部会：json.dumps(payload) + Content-Type: application/json

    timeout=5,
    # ↑ 5 秒内连不上或读不完 → 抛 Timeout
)
# response 是 Response 对象，还没「自动成功」
response.raise_for_status()   # 非 2xx 在这里变成异常
body = response.json()        # 正文 JSON → dict
content = body["choices"][0]["message"]["content"]

若写成 requests.post(url, payload)（少了 json=）：第二个位置参数在 requests 里不是 JSON 身体，行为会错或报错。所以务必写 json=payload。

3.5 返回值不是「结果 dict」，而是 Response

r = requests.post(...)   # r 的类型是 requests.Response
# 你还要自己：
r.status_code            # 看数字
r.raise_for_status()     # 或让失败变异常
r.text                   # 原始字符串
r.json()                 # 再变成 dict/list

和 Java 对照：更像拿到 ResponseEntity<String> 再自己解析，而不是 ResponseEntity<ChatCompletionResponse> 那种已经绑好的 DTO。

4. Response 对象：四个必读属性/方法

写法返回什么用途
response.status_codeintHTTP 状态：200 成功，4xx 客户端错，5xx 服务端错
response.headers类 dict看 Content-Type 等；键名大小写不敏感
response.textstr正文当文本；调试时先看它
response.contentbytes原始字节；下载文件用
response.json()dict/list/…按 JSON 解码；非法 JSON 会抛错
response.urlstr最终请求 URL（含编码后的查询串）

关键提醒（官方 Quickstart）：response.json() 成功不等于这次 HTTP 业务成功。有的服务器在 500 时仍返回 JSON 错误体——必须先看状态码或调用 raise_for_status()。

5. GET 查询参数：用 params，别手拼字符串

response = requests.get(
    "http://127.0.0.1:8765/rag/search",
    params={"q": "Java 接入", "top_k": 2},
    timeout=5,
)
print(response.url)
# .../rag/search?q=Java+%E6%8E%A5%E5%85%A5&top_k=2

params 会做 URL 编码（中文、空格）。手写 url + "?q=" + query 容易漏编码，Agent 工具里禁止这种拼法。

7. timeout 三案：不设 / 单浮点 / 二元组

写法行为建议
不写 timeout可能永远等待生产与 Agent 工具禁止
timeout=5连接+读取共用上限（秒）练习与多数工具够用
timeout=(3.05, 27)(连接超时, 读取超时)官方文档常见推荐形态；读大响应时分开控
requests.get(url, timeout=5)
requests.get(url, timeout=(3.05, 10))

超时抛 requests.Timeout（属于 RequestException）。Agent loop 里超时通常转成「工具失败」观察结果，而不是卡死整轮。

8. 状态码怎么处理：三策略对齐 0007

策略做法适用
读数字分支if response.status_code == 200:同一调用有多种合法状态（少见）
失败即异常response.raise_for_status()默认推荐：非 2xx 抛 HTTPError
转换后上抛捕获后 raise AgentHttpError(...) from error工具边界：给 Agent 看业务语义

顺序口诀：先超时保护 → 再发请求 → raise_for_status → 再 json()。

9. 异常层次 + 标准范式（套在 HTTP 上）

RequestException          # 几乎所有 requests 失败的基类
 ├─ Timeout               # 超时
 ├─ ConnectionError       # DNS/拒连/断网
 └─ HTTPError             # raise_for_status 因 4xx/5xx 抛出
JSON 解码失败 → ValueError / JSONDecodeError（json() 时）
def get_json(path: str) -> object:
    try:
        response = requests.get(BASE + path, timeout=5)
        response.raise_for_status()
        return response.json()
    except requests.Timeout as error:
        raise AgentHttpError(f"请求超时: GET {path}") from error
    except requests.HTTPError as error:
        status = error.response.status_code if error.response else "?"
        raise AgentHttpError(f"HTTP {status}: GET {path}") from error
    except requests.RequestException as error:
        raise AgentHttpError(f"网络失败: GET {path}") from error
    except ValueError as error:
        raise AgentHttpError(f"响应不是合法 JSON: GET {path}") from error

这与 0007「转换后上抛」、0008「JSON 边界」是同一条纪律：底层异常太系统，工具边界要说成人话。

10. Headers 与鉴权：怎么写进 post（加厚）

Header = HTTP 信封上的便签（元数据），不是正文。鉴权 Token、内容类型、自定义追踪 ID 都放这里。

10.0 Bearer 是什么

Bearer 在英文里有「持票人 / 持有者」的意思。写在 HTTP 头里时，表示一种约定好的鉴权方案名：谁持有这张 token（令牌），服务器就暂时把他当成已授权的调用方——不必再传用户名密码。

  • 完整头：名字叫 Authorization，值的形状固定为 Bearer + 一个空格 + token 字符串。
  • token 从哪来：模型厂商 / 云控制台发给你的 API Key，或登录后拿到的 access token。本课假服务不校验；真 API 几乎都要。
  • 和 Basic 的差别（认即可）：Basic 是「用户名:密码」再 Base64；Bearer 是「我已经有一张通行证」，更常见于现代 API / OAuth。
  • 别漏空格、别改大小写习惯：写成 BearerYOUR_TOKEN 或 bearer ... 有的服务会拒；照文档写成 Bearer <token>。
# 头名                  值 = 方案名 + 空格 + 令牌
"Authorization": "Bearer sk-xxxxx"

# 等价拆开看：
scheme = "Bearer"      # 告诉服务器：我用的是 Bearer 方案
token  = "sk-xxxxx"    # 真正的密钥/令牌
headers = {"Authorization": scheme + " " + token}

Java 对照：Spring Security / 网关里常见 Authorization: Bearer ...；Feign 拦截器往同一头塞字符串，语义相同。

10.1 填法（和 json / timeout 一起出现）

headers = {
    "Authorization": "Bearer YOUR_TOKEN",  # Bearer + 空格 + token
    "User-Agent": "agent-learning/0010",   # 可选：表明客户端身份
    # 一般不必手写 Content-Type：用了 json= 时 requests 会自动设 application/json
}

response = requests.post(
    url,                 # ① 去哪
    json=payload,        # ② 身体（dict → JSON 文本）
    headers=headers,     # ③ 头：关键字必须叫 headers，值是 dict[str, str]
    timeout=5,           # ④ 超时
)
  • 参数名是 headers=，不要写成 header= / Header=。
  • 键和值都应是字符串；Token 用拼接："Bearer " + token。
  • 用了 json= 通常不要再手写 Content-Type，以免和自动值冲突。
  • 真密钥放环境变量（如 os.environ["API_KEY"]），不要进 git。

10.3.1 还有别的鉴权手段吗？（扫一眼）

有。HTTP/API 世界里常见的不止 Basic / Bearer。对本课 Agent 主线，认名字 + 知道「凭证放哪」即可，不必逐个实现。

手段一句话凭证通常放哪Agent/模型场景
Bearer持有令牌即授权Authorization: Bearer …最常见（OpenAI 风格等）
自定义 API Key厂商自定头名X-API-Key / api-key 等很常见，以文档为准
Basic用户名+密码（Base64）Authorization: Basic … 或 auth=(u,p)老接口/内网多见
Query 里的 key密钥拼进 URL?api_key=...（即 params）能见到；易进日志，优先避免
Cookie / Session浏览器登录后会话Cookie 头爬站点/后台页时；工具 API 少用
HMAC / 签名用密钥对请求做签名常在自定义头（如时间戳+签名）云厂商开放 API 常见
mTLS（双向证书）客户端也出示证书TLS 层，不是普通 Header高安全内网；本课不练
OAuth2 流程先授权拿 token，再调 API最终调用往往仍是 Bearer「登录授权」复杂；拿到 token 后用法同 §10.0

实操纪律：打开对方 API 文档 → 看它规定用哪种 → 把凭证放进文档指定的抽屉（headers / params / auth），不要自己发明。本课假服务不校验任何鉴权；真模型 API 先按文档抄 Bearer 或 API Key 头。

10.4 Basic 是什么（了解即可）

Basic = HTTP Basic Authentication（基本认证）：另一种写在 Authorization 头里的鉴权方案名。和 Bearer「持有一张令牌」不同，Basic 是把用户名 + 密码交给服务器。

  • 头的真实形状：Authorization: Basic <Base64(用户名:密码)>。Base64 只是编码（可逆），不是加密——所以生产环境必须走 HTTPS。
  • requests 写法：不必自己 Base64，用便捷参数 auth=("user", "pass")，库会自动生成上面的头。
  • 和 Bearer 怎么选：现代模型 API / OAuth 几乎都用 Bearer；Basic 多见于老接口、内网工具、部分文档站。本课 Agent 主线认 Bearer 即可，见到 Basic 能读懂就行。
# 方式 A：便捷参数（推荐认识）
requests.get(url, auth=("alice", "secret"), timeout=5)
# → 实际发出的头类似：
# Authorization: Basic YWxpY2U6c2VjcmV0   （"alice:secret" 的 Base64）

# 方式 B：和 Bearer 对照——方案名不同，后面跟的内容也不同
# Bearer → Authorization: Bearer <token>
# Basic  → Authorization: Basic  <base64(user:pass)>

Java 对照：Spring Security 的 HTTP Basic、或 HttpHeaders.setBasicAuth(user, pass) 同一语义。

11. 和 Agent 工具怎么接

一条最小链路：

  1. rag_search 工具内部 GET /rag/search → 得到 hits（检索命中列表，见下）
  2. 拼上下文（0006 的 join）
  3. chat_completion 工具内部 POST /v1/chat/completions → 得到助手文本
  4. 任一步失败 → AgentHttpError → Agent loop 当作 tool error 观察

11.1 hits 是什么

hit 英文是「命中」；检索场景里 hits = 本次查询命中的文档/片段列表（通常已按相关度排好，条数受 top_k 限制）。

  • 不是 HTTP 状态，也不是「点击次数」；就是搜索结果数组的一个常用字段名（Elasticsearch 等也爱用 hits）。
  • 本课假 API 返回形如：
{
  "query": "Java 如何接入 Agent",
  "hits": [
    {"id": "d1", "score": 0.91, "text": "Harness 把工具接在模型外：与「Java 如何接入 Agent」相关"},
    {"id": "d2", "score": 0.77, "text": "RAG 先检索再生成，减少胡编。"}
  ]
}
  • 每一项 hit ≈ 一条候选知识：id 标识、score 相关度、text 正文（真系统里还可能有 title、url、chunk 等）。
  • rag_search 做的事：HTTP 拿到整份 JSON → data["hits"] → 返回 list[dict]，供后面 join 成 prompt 上下文。
hits = rag_search(...)           # list[dict]，例如 2 条
context = "\n".join(h["text"] for h in hits)   # 拼成给模型看的资料

主脚本 http_agent_client.py 里参数对应关系：

get_json(path, params=...)  →  requests.get(url, params=..., timeout=...)
post_json(path, payload)    →  requests.post(url, json=payload, timeout=...)
rag_search(query, top_k)    →  GET + params={"q": query, "top_k": top_k}
chat_completion(text)       →  POST + json={"model", "messages"}

读 post_json 时盯住：身体必须写 json=payload，不能写成 requests.post(url, payload)。

fake_api_server.py 导读（① 先读）

先定心态：本课主线是学客户端怎么发 HTTP；这个脚本扮演「对方」——假 RAG + 假 chat API。不必学成 HTTP 服务器开发，但要能看懂：客户端打的 URL / 参数 / JSON，在这里怎么被接住、怎么回 JSON。

你跑 client / examples          fake_api_server（本脚本）
        |  GET /rag/search?q=...     |
        | ------------------------> |  do_GET 读 path + 查询串
        |  200 {"hits":[...]}        |  _send_json 写回
        | <------------------------ |

        |  POST /v1/chat/completions |
        |  body: {"model","messages"}|
        | ------------------------> |  do_POST 读 rfile → json.loads
        |  200 {"choices":[...]}     |  _send_json 写回

整体结构（三块）

  1. 启动（main）：ThreadingHTTPServer 在 127.0.0.1:8765 监听 → serve_forever() 一直等请求。
  2. 路由（do_GET / do_POST）：按路径分支，决定返回 200/404/400 和 JSON 内容。
  3. 发响应（_send_json）：把 Python dict 变成 JSON 字节，写上状态码和头，通过 wfile 发出去。

第一次见的名字：速查

名字是什么在本脚本里干什么
ThreadingHTTPServer 标准库里的小型 HTTP 服务器（每个请求开一个线程处理） ThreadingHTTPServer((HOST, PORT), FakeAgentAPI) 绑定地址并开始接客
BaseHTTPRequestHandler 处理「一次 HTTP 请求」的基类；子类重写方法即可 class FakeAgentAPI(BaseHTTPRequestHandler)
do_GET / do_POST 约定俗成的方法名：收到 GET/POST 时框架自动调用 里面写「这条路径返回什么」
self.path 本次请求的 path + 查询串，如 /rag/search?q=harness&top_k=2 用 urlparse 拆成路径和 ?后面
urlparse 把 URL 拆成 path、query 等零件 parsed.path → /rag/search；parsed.query → q=harness&top_k=2
parse_qs 把查询串解析成 dict；每个键对应 list（因为同名参数可出现多次） {"q": ["harness"], "top_k": ["2"]}
self.headers 客户端发来的 HTTP 头（类 dict） POST 时读 Content-Length 知道 body 多长
self.rfile 读客户端发来的请求体（bytes 流） self.rfile.read(length) 读出 JSON 原文
self.wfile 写响应体给客户端（bytes 流） self.wfile.write(body) 发出 JSON 字节
send_response / send_header / end_headers 组 HTTP 响应：状态码 → 头字段 → 头结束 在 wfile.write 之前调用
.encode("utf-8") / .decode("utf-8") 字符串 ↔ 字节；网络传的是字节 发响应前 dumps 后 encode；收 body 后 decode 再 loads
serve_forever() 阻塞循环：一直处理请求，直到进程结束 所以假服务终端要常驻
KeyboardInterrupt 按 Ctrl+C 时抛的异常 捕获后 server_close() 礼貌关机

Java 对照：ThreadingHTTPServer ≈ 内嵌 Tomcat/简单 Servlet 容器；do_GET ≈ @GetMapping 处理方法；_send_json ≈ 手动写 ResponseEntity + JSON body。

分段读代码

启动：main()

server = ThreadingHTTPServer((HOST, PORT), FakeAgentAPI)
server.serve_forever()
  • (HOST, PORT) = 元组：127.0.0.1 是本机回环地址，只有本机能连；8765 是端口。
  • 第二个参数 FakeAgentAPI：告诉服务器「每个请求用哪个 Handler 类来处理」。
  • if __name__ == "__main__"：只有直接 python fake_api_server.py 时才跑 main()；被 import 时不自动起服务。

发 JSON：_send_json(status, payload)

body = json.dumps(payload, ensure_ascii=False).encode("utf-8")
self.send_response(status)                    # 如 200、404
self.send_header("Content-Type", "...")     # 告诉对方：正文是 JSON
self.send_header("Content-Length", str(len(body)))
self.end_headers()                            # 头结束
self.wfile.write(body)                        # 正文字节写出

这是「服务端版的响应组装」——和客户端 response.json() 读到的内容对应。客户端 requests 帮你做好了读；这里是手写「怎么发」。

GET 路由：do_GET

parsed = urlparse(self.path)
if parsed.path == "/health": ...
if parsed.path == "/rag/search":
    qs = parse_qs(parsed.query)
    query = (qs.get("q") or [""])[0]      # 见下「易混写法」
    top_k_raw = (qs.get("top_k") or ["3"])[0]
    top_k = max(1, min(int(top_k_raw), 10))  # 限制 1～10
    self._send_json(200, {"query": query, "hits": docs[:top_k]})

易混写法 (qs.get("q") or [""])[0]：因为 parse_qs 返回的是「键 → 列表」，没有 q 时用空字符串列表 [""]，再取第一个元素。等价于「取查询参数 q，缺省为空串」。

docs[:top_k]：列表切片，只返回前 top_k 条 hit——和客户端 params={"top_k": 2} 对上。

POST 路由：do_POST

length = int(self.headers.get("Content-Length", "0"))
raw = self.rfile.read(length) if length else b"{}"
data = json.loads(raw.decode("utf-8") or "{}")
  • POST 的 JSON 在身体里，不在 URL；必须先读长度再 read。
  • b"{}"：bytes 字面量；空 body 时当空对象。
  • 后面从 data 取 model、messages，拼假回复，形状模仿 OpenAI chat completion（choices[0].message.content），方便 chat_completion 解析。
for msg in reversed(messages):
    if msg.get("role") == "user":
        last_user = str(msg.get("content", ""))
        break

reversed(messages)：从后往前找，取最后一条 user 消息（多轮对话时常见需求）。

常见坑 + 边界

  • 忘记 timeout：服务挂起 → 脚本假死；Agent 工具必须设超时。
  • 只调 json() 不看状态：错误页也可能是 JSON，业务会误读。
  • data= 当 JSON：Content-Type 变表单，服务端解析失败或字段全空。
  • 手拼 query：中文/空格炸掉；用 params=。
  • 密钥进仓库：Token 放环境变量或本地未跟踪配置，不要写死在课件脚本里。
  • 异常范围：窄 try；不要把整个 agent loop 塞进一个裸 except。
  • Java 易混：requests 默认宽松（非 2xx 不自动抛）；要显式 raise_for_status。
