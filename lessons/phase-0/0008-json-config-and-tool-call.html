系统讲解

1. JSON 是「文本协议」，dict 是「内存结构」

JSON（JavaScript Object Notation）是一种文本数据交换格式：磁盘上是一段 UTF-8 字符串，HTTP body 里也是字符串，模型有时也会输出一段 JSON 字符串。Python 的 dict/list 活在内存里，不能直接写进文件或发给别的进程——需要先编码成 JSON 文本；读回来再解码成 Python 对象。

# 内存里（Python）
call = {"name": "rag_search", "arguments": {"top_k": 3}}

# 文本里（JSON）—— 注意 true/false/null 与引号规则
# {"name": "rag_search", "arguments": {"top_k": 3}}

口诀：dict 给程序用，JSON 给边界用（文件、网络、模型输出）。官方模块文档：json — JSON encoder and decoder。

2. 类型对照表（必须背）

编解码时类型会按固定表转换。搞错这一表，后面所有「top_k 怎么变成 int」都会晕。

JSONPython（解码后）注意
object {...}dict键在 JSON 里必须是双引号字符串
array [...]list元组编码进 JSON 也会变成 array，解码回来是 list
stringstr只用双引号，单引号非法
numberint 或 float3 → int；3.0 → float
true / falseTrue / False大小写敏感；JSON 里不能写 Python 的 True
nullNone不是字符串 "null"
import json

text = '{"ok": true, "n": 3, "msg": null}'
data = json.loads(text)
print(data["ok"] is True)   # True
print(data["n"] == 3)       # True
print(data["msg"] is None)  # True

3. 四个函数：先分清「字符串」还是「文件」

这是本课最重要的易混点，写满三种用法：

场景API方向典型用途
内存字符串json.dumps(obj)对象 → str拼 HTTP body、打印、交给模型看
内存字符串json.loads(s)str → 对象解析模型输出、解析响应 body
磁盘文件json.dump(obj, file)对象 → 文件写配置、写运行状态
磁盘文件json.load(file)文件 → 对象读配置、读缓存

记忆法：名字带 s 的（dumps/loads）走 string；不带 s 的（dump/load）走文件对象。不要把 loads 喂给文件路径字符串却期望它去读盘——它只会把这个路径字符串本身当成「待解析的 JSON 文本」，几乎一定失败。

4. dumps / loads：字符串通道详解

import json

payload = {
    "name": "rag_search",
    "arguments": {"query": "harness", "top_k": 3},
}

text = json.dumps(payload, ensure_ascii=False)
print(type(text), text)          # <class 'str'> ...

again = json.loads(text)
print(again["name"])             # rag_search
print(type(again["arguments"]))  # <class 'dict'>

dumps 的常用关键字参数：

参数默认作用
ensure_asciiTrueTrue 时非 ASCII（如中文）会变成 \uXXXX；人读配置请用 False
indentNone设为 2 或 4 会美化换行缩进；调试友好，文件略大
sort_keysFalseTrue 时按键名排序，便于 diff / 测试快照
# 默认 ensure_ascii=True：中文被转义（机器无关，但人难看）
json.dumps({"q": "检索"}, ensure_ascii=True)
# '{"q": "\\u68c0\\u7d22"}'

# 配置文件推荐：
json.dumps({"q": "检索"}, ensure_ascii=False, indent=2)

5. dump / load：文件通道（接 0007）

from pathlib import Path
import json

path = Path(__file__).parent / "agent_config.json"

with open(path, "r", encoding="utf-8") as file:
    config = json.load(file)          # 文件 → dict

config["max_turns"] = 10

with open(path, "w", encoding="utf-8") as file:
    json.dump(config, file, ensure_ascii=False, indent=2)
    file.write("\n")                  # 可选：末尾换行，对 git diff 更友好

路径仍然用 Path(__file__).parent（0007 三案）。文本模式 + encoding="utf-8" 与 JSON 文本配套。

等价写法（小文件也可以）：

text = path.read_text(encoding="utf-8")
config = json.loads(text)

path.write_text(
    json.dumps(config, ensure_ascii=False, indent=2) + "\n",
    encoding="utf-8",
)

dump(file) 与 write_text(dumps(...)) 都能落盘；前者少一次大字符串拼接，习惯上配置读写更常见 dump/load。

6. 数字三案：JSON 数字 / 字符串数字 / 缺键

外部世界（模型、前端、手写配置）经常把数字写成字符串。必须分清三种输入，再统一成内部 int：

输入 JSON 片段data.get("top_k", 3) 得到什么正确归一化
{"top_k": 3}int 3int(...) 仍安全
{"top_k": "3"}str "3"必须 int(...)，否则切片/循环会错
{}默认值 3（int）int(data.get("top_k", 3))
def normalize_top_k(data: dict) -> int:
    return int(data.get("top_k", 3))

print(normalize_top_k(json.loads('{"top_k": 3}')))
print(normalize_top_k(json.loads('{"top_k": "3"}')))
print(normalize_top_k(json.loads('{}')))

这和 0002/0006 的提醒同一条线：边界把类型收干净，业务层假设类型稳定。

7. 什么叫「合法 JSON」：常见非法写法

非法例子为什么挂
{'a': 1}键和字符串必须用双引号，不能用单引号
{"a": 1,}尾逗号不允许（Python dict 字面量可以，JSON 不行）
{a: 1}键必须是字符串
{"ok": True}要用 true，不是 Python 的 True
{"x": None}要用 null

解析失败抛 json.JSONDecodeError（是 ValueError 的子类）。它带 lineno、colno、pos，适合日志定位。

8. 异常标准范式怎么套在 JSON 上

直接复用 0007 心法：窄 try、具体 except、边界改语义。

import json
from pathlib import Path

def load_config(path: Path) -> dict:
    try:
        with open(path, "r", encoding="utf-8") as file:
            data = json.load(file)
    except FileNotFoundError as error:
        raise FileNotFoundError(f"配置文件不存在: {path}") from error
    except json.JSONDecodeError as error:
        raise ValueError(f"配置不是合法 JSON: {path}") from error

    if not isinstance(data, dict):
        raise TypeError("配置根节点必须是对象(dict)")
    return data
  • 局部恢复：可选配置缺失 → 用内置默认 dict（要在文档里写清）。
  • 转换后上抛：必选配置坏了 → ValueError("配置不是合法 JSON")。
  • 不捕获：更底层的纯 json.loads 小函数可以不管，交给边界。

解析成功后仍要做结构校验：JSON 只保证语法，不保证有 name 字段或 arguments 是对象。

9. 键永远是字符串：往返可能变样

original = {1: "int-key"}
text = json.dumps(original)
back = json.loads(text)
print(back)          # {'1': 'int-key'}  —— 键变成了字符串 '1'
print(original == back)  # False

官方明确：JSON 对象的键只能是 string；编码时非 str 键会被转成字符串，再解码就回不来。Agent 配置与 tool_call 请从头使用字符串键。

10. 和 0006 tool_call 怎么接起来

0006 假定你已经有一个 Python dict。本课补上「dict 从哪来」：

raw = '{"name":"rag_search","arguments":{"query":"x","top_k":"2"}}'
call = json.loads(raw)                 # str → dict
name = call["name"]
args = call.get("arguments", {})

常见坑 + 边界

  • loads 不是读文件：json.loads("agent_config.json") 会把文件名当 JSON 文本解析。
  • True / true：手写 JSON 文件时写 Python 布尔会直接语法错误。
  • 尾逗号：Python 允许，JSON 不允许。
  • ensure_ascii 默认 True：中文配置变 \u 转义；人读文件请 False。
  • 数字字符串：外部 "3" 不是 int；边界统一 int(...)。
  • 根类型：配置与 tool_call 通常要求根是 object；若根是 array，先 isinstance(..., dict) 挡掉。
  • 多次 dump 到同一文件：JSON 不是「多帧协议」，反复 dump 追加会得到非法拼接；应一次写完整对象，或写 JSON Lines（本课不展开）。
  • 不可序列化对象：set、datetime、Path 不能直接 dumps，需先转成 list/str；否则 TypeError。
  • Java 易混：这里没有编译期 DTO，校验是你的责任。
