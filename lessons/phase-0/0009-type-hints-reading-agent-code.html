系统讲解

1. 标注是什么：说明书，不是运行时护栏（默认）

类型标注（type hints）写在变量、参数、返回值上，说明作者期望的类型形状。默认情况下 Python 不会在运行时因为标注不匹配而报错——这和 Java 编译期检查不同。

def greet(name: str) -> str:
    return f"hello, {name}"

print(greet.__annotations__)
# {'name': 'str', 'return': 'str'}

标注存在 __annotations__ 字典里，IDE、mypy、pyright 会读它们帮你补全和报错。你读 Agent 代码时，先看函数签名再进函数体。

位置写法例子
参数name: strdef run(query: str, top_k: int = 3)

你在 load_knowledge.py 第 6 行见过的 documents: list[dict[str, str]] = [] 就是在说：这个列表里每个元素是「键值都是 str 的 dict」——和 Java List<Map<String,String>> 同一意图。

3. 容器泛型：list / dict / set / tuple

Python 3.9+ 推荐直接用内置类型加方括号（不必从 typing 导入 List/Dict）：

names: list[str] = ["rag_search", "final"]
scores: dict[str, float] = {"a": 0.9, "b": 0.7}
tags: set[str] = {"rag", "tool"}
pair: tuple[str, int] = ("query", 3)

嵌套时从外往里读：list[dict[str, float]] = 「dict 列表，每个 dict 的键是 str、值是 float」——典型检索 hits 结构。

def pick_top_k(
    hits: list[dict[str, float]],
    top_k: int = 3,
) -> list[dict[str, float]]:
    return sorted(hits, key=lambda h: h["score"], reverse=True)[:top_k]

「方括号」这套就是泛型：把类型本身当参数——容器先留空位，使用时再填具体类型。空位填得越满，信息量越大：

list[dict[str, float]]   # 「列表」这个收纳盒贴了标签：每个元素是 dict，键 str、值 float
list                     # 光说"是个列表"，什么都可能装 —— 读代码等于没说

对照 Java：list[dict[str, float]] 就是 List<Map<String, Float>>，只是尖括号 <> 换成了方括号 []。（自己写泛型函数要用 TypeVar 定义类型变量 T，本课跳过；现阶段读懂方括号即可。）

4. Any：边界上诚实地说「形状未验」

json.load 之后你得到的是松散对象。在刚进门的函数里用 Any 或 dict[str, Any]，表示「我还没验证字段」；校验后再收成更具体的类型。

from typing import Any

def load_config(path: Path) -> dict[str, Any]:
    ...
    return data   # 仍是松散 dict

def summarize_config(config: dict[str, Any]) -> ConfigSummary:
    ...           # 在这里 int()/str()/isinstance 归一化

口诀：Any 只留在边界一层，不要一路 Any 传到业务深处。

5. None 三案（必背）

场景写法含义
必填，不允许空name: str调用方必须传 str；若可能缺字段用校验抛错
可选参数，默认就是 Nonepath: str | None = None没传时是 None；函数内先判断
可能返回空-> str | None有时返回 str，有时返回 None
def load_label(path: str | None = None) -> str:
    if path is None:
        return "default-config"
    return path

3.10+ 用 X | None；旧代码常见 Optional[X]（等价）。标注说可 None，不等于你可以省略 if x is None 判断。

先懂 |：str | None 读作「要么是 str，要么是 None」，二选一（联合类型）。三案各自的完整样子：

① 必填        def greet(name: str) -> str: ...
              greet()      # TypeError：缺参数，调用时就拦住
              greet(None)  # 类型检查器标红：None 不是 str

② 可选参数    def load(path: str | None = None):
                  if path is None:            # 函数内先判断
                      path = "default.json"
              # 「= None」管"不传时填什么"；「str | None」管"传了之后的合法范围"

③ 可能返回空  def find_user(uid: int) -> str | None:
                  if uid in users:
                      return users[uid]
                  return None                  # 没查到只能给 None，不许硬编名字
场景调用方能不传？None 出现时谁处理
必填非空 name: str不能，缺了直接报错不该出现；传错当场炸
可选参数 path: str | None = None能函数内先判断再用
可能空返回 -> str | None—调用方拿到后先 if x is None

口诀：参数侧的 None 用默认值表达（= None），返回侧的 None 用联合类型表达（-> X | None）；谁拿到 None，谁负责判断。与 0008 的 .get("arguments", {}) 同一条线——把「可能没有」显式写进接口，而不是埋雷。

6. from __future__ import annotations 是干什么的

文件顶部常见这一行（你的 0008 脚本已有）。它让标注在定义时先当字符串存，推迟解析：

  • 可以用尚未定义的类名做返回类型（前向引用）
  • 避免运行时立刻求值带来的循环引用问题
  • 标注里写 list[str] 不会在旧版本里立刻去构造泛型对象
from __future__ import annotations

class AgentSession:
    def add_tool_result(self, name: str, payload: dict[str, str]) -> None:
        ...

读代码时：看到文件第一行有它，知道标注是「现代 Python 项目」风格，和开源 agent 仓一致。

# 加了它之后，标注不再在定义时求值，而是存成字符串：
def g(x: int) -> None: ...
print(g.__annotations__)
# {'x': 'int'}        ← 字符串！不加这行则是 {'x': <class 'int'>}（真实类型对象）

它解决两个实际问题：

  • 旧解释器跑新语法（最常见动机）：str | None 这类写法要 3.10+ 运行时支持；在 3.9 上不加这行，函数定义那一刻就抛 TypeError: unsupported operand type(s) for |。加了则标注只存文本、不求值，顺利定义。
  • 前向引用：标注里用了「文件更下方才定义」的类名，也不会 NameError。

注意它不做什么：不会打开任何运行时类型检查（Python 默认就没有）。副作用：运行时从 __annotations__ 拿到的是文本；程序要真实类型对象得用 get_type_hints()（见讲解 9）。

7. TypedDict：给 dict 一张字段表（轻量 DTO）

当 dict 形状稳定（如配置摘要、工具结果），可用 TypedDict 描述有哪些键、各是什么类型——仍是运行时 dict，不是 Java class。

from typing import TypedDict

class ConfigSummary(TypedDict):
    model: str
    max_turns: int
    rag_enabled: bool
    top_k: int
    knowledge_dir: str
    allowed_tools: list[str]

def summarize_config(config: dict[str, Any]) -> ConfigSummary:
    return {
        "model": str(config.get("model", "unknown")),
        "max_turns": int(config.get("max_turns", 4)),
        ...
    }

total=False 表示字段可缺省（用于描述 JSON 里可选块，如 RagConfig）。读代码：见到 TypedDict，把它当「这份 dict 应该长什么样」的注释表。

8. 读开源代码的标准流程

  1. 看函数签名：参数类型、返回类型、默认值。
  2. 看边界函数是否用 Any / dict[str, Any]——那里通常要做 isinstance。
  3. 看内部是否收成 TypedDict 或具体 list[dict[...]]。
  4. 不信标注：JSON、模型输出、外部 API 一律当不可信，延续 0006/0008 校验链。
# 读签名
def parse_tool_call(raw: dict[str, Any]) -> tuple[str, dict[str, Any]]:
    ...

# 看边界
if not isinstance(arguments, dict):
    raise TypeError("arguments 必须是对象")

顺带读 -> tuple[str, dict]：Python 函数只能 return 一个东西；要交出「工具名 + 参数」两件结果，就打包成元组，调用方按位置解包 name, arguments = parse_tool_call(call)。return a, b 本质是 return (a, b)——逗号创建元组，括号可省。

9.1 文件顶：frozenset 白名单

KNOWN_TOOLS = frozenset({"rag_search", "read_file", "final"})
写法可变？何时用

frozenset({...})不可变写死的白名单、当 dict 的键

工具名白名单不应被别处改掉；用 frozenset 表达「这份名单是常量」。判断 name not in KNOWN_TOOLS 与 set 一样快。对照 Java：有点像 Set.of(...) 得到的不可变集合。

9.3 核心签名：一行拆成四块

def parse_tool_call(raw: dict[str, Any]) -> tuple[str, dict[str, Any]]:
片段读法
raw参数名：原始 tool_call
: dict[str, Any]入参形状：键 str，值尚未验（Any）
->后面是返回类型
tuple[str, dict[str, Any]]返回二元组：第 0 个 str（工具名），第 1 个 dict（arguments）

为何入参是 Any 值、不是 TypedDict？因为 JSON 刚进来时字段可能缺失、类型可能是错的——标注承认「松」，函数体里用 isinstance 变「紧」。

# 调用方这样接两个返回值（元组解包）
name, arguments = parse_tool_call(raw)
# name -> "rag_search"
# arguments -> {"query": "...", "top_k": "2"}  # top_k 可能仍是字符串！

9.4 函数体：标注之后仍要校验

name = raw.get("name")           # 缺键 → None，不是抛 KeyError
if not isinstance(name, str):    # 挡掉 None / 数字 / 嵌套对象
    raise TypeError(...)
if name not in KNOWN_TOOLS:      # 类型对了，业务仍可能非法
    raise ValueError(...)

arguments = raw.get("arguments", {})
if not isinstance(arguments, dict):
    raise TypeError(...)
return name, arguments           # 打包成元组交出去

两条异常分工（接 0007）：

  • TypeError：形状/类型不对（不是 str、不是 dict）
  • ValueError：类型对了但业务不允许（未知工具名）

9.5 dict[str, int | str]：值可以是联合类型

def normalize_rag_args(arguments: dict[str, Any]) -> dict[str, int | str]:
    ...
    return {"query": query, "top_k": top_k}  # query:str, top_k:int

int | str 读作「int 或 str」。用在 dict 值位置时意思是：每个值各自属于其中一种——不是要求同一个值同时是两种。这里 query 是 str，top_k 是 int，所以整个返回值标成 dict[str, int | str]。

若字段形状更固定，也可用 TypedDict（见 typed_config.py）写清「query 一定是 str、top_k 一定是 int」。

9.6 {"name": name, **normalized}：字典解包

normalized = {"query": "...", "top_k": 2}
print({"name": name, **normalized})
# 得到 {"name": "rag_search", "query": "...", "top_k": 2}

** 用在 dict 字面量里：把另一个 dict 的键值对摊开合并进新 dict。和 0004 的 fn(**kwargs) 是同一套「拆开映射」直觉，只是这里拆进字面量而不是函数参数。若键冲突，后写的覆盖先写的。

10. __annotations__ vs get_type_hints：原始便签 vs 解析成品

from typing import get_type_hints

def pick_top_k(hits: list[dict[str, float]], top_k: int = 3) -> list[dict[str, float]]:
    ...

print(pick_top_k.__annotations__)
# {'hits': 'list[dict[str, float]]', 'top_k': 'int', 'return': 'list[dict[str, float]]'}
# ↑ 文件顶上有 from __future__ import annotations 时，全是字符串（原样存档，不求值）

print(get_type_hints(pick_top_k))
# {'hits': list[dict[str, float]], 'top_k': <class 'int'>, 'return': list[dict[str, float]]}
# ↑ 把字符串求值回真实类型对象
取法行为适用
fn.__annotations__存了什么给什么；惰性模式下是文本人看一眼
get_type_hints(fn)把字符串求值回对象（在模块命名空间查名字），并给未标注参数补 Any程序要消费类型信息（写校验器/工具）

日常读 agent 代码，认识 __annotations__ 即可。

11. 标注 + 异常：类型错了抛什么

标注不挡运行时错误，所以边界仍用 0007 范式：

  • 形状不对 → TypeError（isinstance 失败）
  • 业务不允许 → ValueError（如 unknown tool）
  • JSON 语法坏 → json.JSONDecodeError → 边界转成 ValueError

返回类型 -> None 表示「不返回有用值」；不要和参数 None 混淆。

常见坑 + 边界

  • 标注 ≠ 校验：写了 str 仍可能传入 int；边界必须 isinstance。
  • JSON 后仍是松散 dict：不要假设有 TypedDict 字段就一定存在。
  • list vs List：新代码优先 list[str]；读老库可能仍见 from typing import List。
  • | None vs 默认 None：前者是类型声明；后者是运行时默认值——常一起出现。
  • -> None：函数不返回业务值；别写成 -> None 却又 return 42（静态检查会骂）。
  • 过度标注：每个局部变量都标反而噪；优先标函数边界和公共 API。
  • Java 易混：Python 没有编译期强制；面试时说「标注 + 运行时校验 / 静态检查可选」。
