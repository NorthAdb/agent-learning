系统讲解

1. 两套公式怎么叠

1.1 它是什么？

书在 §1.2 把 LLM 称作 Model，把 Agent 边界内、模型之外的代码/配置/服务统称为 Harness。 写成：Agent = Model + Harness。

原文： 第01章.md · §1.2 L261 · 公式 L270 · 「最小 Demo / 生产」L273 

0017  Agent = LLM + 上下文 + 工具
0018  Agent = Model + Harness

Model          = LLM（大脑，同一块）
最小 Harness   = 上下文管理 + 工具接口
生产 Harness   = 最小 + 约束 + 验证 + 纠正

不是换了一套分类把 0017 作废。 0017 回答「有哪三块零件」；本课回答「零件里谁做决策、谁提供世界」。 眼睛和手脚这一侧，就是最小 harness。

后训练：预训练之后继续用数据改权重（微调、强化学习等）。 那是在改 Agency。本书第八章才展开；本仓库地基阶段不做。

2. Agency 来自模型，不是来自编排

2.1 它是什么？

Agency 是英语里「能自己感知、推理、采取行动」的那种能力。 本课用的定义来自 North，不是书 Ch1——书里用「大脑 / LLM」，没有写 Agency 这个词。

Agency -- 感知、推理、行动的能力 -- 来自模型训练，不是来自外部代码的编排。

原文就这一句，在 learn-claude-code-north/README-zh.md · 标题 L5「Agency 来自模型，Agent 产品 = 模型 + Harness」 · 加粗定义 L9 · 再解释一遍 L11 节「Agency 从哪来」

拆开记三件事：

  • 是什么：感知环境、推理目标、采取行动的能力（不是某一个 Python 类名）。
  • 从哪来：模型训练（权重里），不是你写的 if-else / 节点图给它「赋予」的。
  • 和 Harness 的差别：模型是驾驶者（有 Agency）；harness 是载具（工具、上下文、权限）。同一句 L9：「模型是驾驶者，harness 是载具。」

提示词水管工（North 的贬义说法）：把 LLM API 用分支、节点图、提示词链串起来， 当作「构建了 Agent」。模型只在节点里当文本补全。 那是 0017 的工作流（或更碎的规则管道），不是把决策交给模型。

原文：README L31「Agent 不是什么」 · 「不可能通过工程手段编码出 agency」在 L39

2.2 三案：有人说「我在开发 Agent」

案实际在做判定
① 收集轨迹、微调 / RL，改权重 开发 Agency。DeepMind / OpenAI / Anthropic 的本义。本仓库不做
② 实现工具、拼上下文、管权限、跑验证 开发 Harness。你以后读 North s01–s20 就是这个
③ 拖拽节点、硬编码路由、祈祷胶水涌现智能 不是。水管工 / 工作流，装不出 Agency

使命选的是 ②。阶段 2 起跑 code.py，不是去训模型，也不是去学 LangGraph。

「我在开发 Agent」只能是训练或造 harness 这两种：README L43–50

3. 最小 vs 生产：约束、验证、纠正

书：能跑的 Demo 只要 Model + 会拼上下文、会暴露工具的 Harness。可靠产品还要三层保障。

原文：书 §1.2 L273 「最小 Demo 只需 Model 和能构造上下文、暴露工具的 Harness；生产系统还要…约束、验证和纠正」。 三保障表在 L277。 伪代码： constrain L288 / verify L290 / correct L291。

词是什么干什么别和谁混
约束 限定能做 / 不能做 权限、沙箱、金额上限、审批 不是把下一步写死（那是工作流）
验证 检查做得对不对 测试、lint、显式完成定义 不是模型口头说「完成了」
纠正 错了怎么补救 重试、回退、换工具 不是验证本身；细节以后按章补

三案（Harness 厚度）： ① 最小只拼上下文 + 跑工具； ② 生产加上三保障； ③ 假的只有一份超长 prompt——那不是 harness。

4. North 五件套：同一层载具的另一种切法

North 把编程 agent 的 harness 写成： Tools + Knowledge + Observation + Action Interfaces + Permissions。 和书的「上下文管理 / 工具接口 / 约束…」描述同一层，不必背成两套产品。

原文：README L54–61 公式块；工程师日常 L69。

North一句话多半落在书的
Tools / Action能调的动作；以及怎么把动作打到环境（CLI、API）工具接口
Knowledge文档、规范、风格指南（按需加载，别一次塞满）上下文管理
Observationgit diff、错误日志、测试输出 → 转成上下文上下文管理
Permissions沙箱、审批、信任边界约束

North 还列了 harness 工程师日常：实现工具、策划知识、管理上下文、控制权限。 「收集轨迹去训练下一代模型」是加分项，不是本阶段作业。

常见坑 + 边界

  • 两套公式打架：不打架。0017 是零件；本课是驾驶者 vs 载具。
  • 把整个 Cursor 叫「模型」：模型只是大脑；循环、工具、权限是 harness。
  • 以为写了 AGENTS.md 就有完整 harness：那是指令的一部分；还要工具接口和治理。L02 以后再拆。
  • 用节点图「做出」Agency：编排不出感知—推理—行动；那是水管工。
  • 约束 = 写死步骤：约束是护栏；步骤由模型选（自主 Agent）。
