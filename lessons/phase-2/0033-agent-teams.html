s13：队友各写各的上下文，结果从收件箱回来

s12 到点之后仍是同一个 Agent，整段后端重构会堆进一份 messages。 本课把工作拆给持久队友：Lead 先提出分工并等你确认，队友各自跑循环， 用文件收件箱把结果送回 Lead，空闲时再从共享任务板认领下一项。 需要分开改代码时，任务可以绑一个 worktree。大目标仍是造 harness： 谁和谁说话、在哪个目录改，由运行时规定，不靠模型互相看见对方的工具结果。

为什么现在学？

配置、认证、测试可以并行，但一个 Agent 依次做会更久，早期细节也会离开上下文。 用户通常只说目标，不会自己设计团队。Harness 要规定：谁决定加人、上下文是否共享、 结果怎样回来、空闲的人能不能自己领任务、改文件用哪个目录、关机和审批怎样对上号。

s06 的 subagent 做完一次就结束，中间过程丢弃，只交回一份摘要。 队友要跨任务留着身份，还能收消息。s10 的任务板仍是进度文件； 本章加上的是「多个循环怎么用这块板」，不是另一套任务字段。

和 Java 怎么对照

s13 概念Java 直觉关键差异
Lead / 队友 一个协调线程加若干 worker 每个 worker 有自己的对话数组。不能把别人的 tool_result 放进自己的推理。
.mailboxes/*.jsonl 每个消费者一个队列 读的时候把文件删掉。没有第二个消费者再读同一批。

计划闸门 审批通过前禁止写操作 闸门在工具分发层，不靠队友「记得先别改文件」。

规则先看四条小例

例 1：没确认就不要启动

加人会改变谁可以改工作区。系统提示要求先写出小团队的职责，等你确认。 代码不会替模型检查「这句话算不算确认」。它提供 spawn_teammate， 约束写在提示里。你看到 Lead 还没等回复就启动，那是模型没遵守提示，不是运行时又做了一道闸门。

一旦调用 spawn_teammate 且带了 task_id，运行时会在开线程之前认领。 认领失败会把刚写下的队友状态抹掉，并返回 Cannot spawn teammate。没有半个已启动的线程。

细节实现

没有任务就没有 cwd

队友的 bash、读、写、改、glob 都先问 current_cwd。 assignment 里没有这个名字，工具返回「先认领任务」，不会偷偷用仓库根目录。 任务没绑 worktree 时，解析结果是 WORKDIR。绑了就用那个目录。 绑定损坏时认领失败，同样不退回仓库根。

complete_task 成功只把状态写成 completed，不立刻清 assignment。 当前这轮模型里后面的工具仍用这个目录。回到 IDLE 时才 release_completed_assignment。 完成失败则目录保持不变，方便改完再试。

cwd： code.py L1192–1217。 释放时机： L1309–1313。

worktree 不是沙箱，模型也不能删

create_worktree 只给 Lead。任务必须还是 pending、没人认领、还没绑定。 Git 失败若已经留下分支或 checkout，运行时报告部分操作，任务保持未绑定，目录留给人处理。

remove_worktree 不是模型工具。pending 或 in_progress 的绑定、当前轮还握着的 lease，都会拒绝移除。 没明确丢弃改动时，脏工作区也拒绝清理。移除成功仍保留仓库里的 wt/<name> 分支。 任务完成不等于目录已经合并或删除。

观察一：确认之前没有队友线程

第一轮终端里应是分工说明，而不是 [teammate] ... spawned。 你回复开始之后，才应看到任务创建、认领和 spawned。

观察二：结果和空闲是两条

.mailboxes/ 或终端 [bus] 里应能区分 result 和 idle_notification。 Lead 的下一轮由运行时唤醒，不需要你提醒它去读收件箱。

观察三：目录只跟着认领走

.worktrees/ 只出现在绑了 worktree 的任务上。 没认领的队友若调用写文件，结果应是先认领，而不是写进仓库根。

常见坑 + 边界

  • 队友就是 s06 多叫几次：不是。队友线程跨任务保留 messages，并用收件箱双向通信。
  • 把两个队友的工具结果放进同一份 messages：本章不这样做。各写各的数组。
  • 模型可以调用 check_inbox：没有这个工具。消费是运行时的事。
  • result 已经表示人闲了：不表示。闲不闲看后一条 idle_notification。
  • 扫描到了就一定领到：不一定。认领时会重读状态，别人可能已经领走。
  • worktree 坏了就用仓库根：不会。认领直接失败。
  • 没认领也能在仓库根改文件：队友的文件和 Shell 工具会拒绝。
  • complete 一返回，目录立刻切走：不会。要等这轮结束、回到 IDLE 才释放。
  • 计划被拒仍可 bash：不可以。闸门挡住 bash、写、改。
  • 队友遇到危险命令会问你 Allow?：不会。它不读键盘，把 permission 错误交回去。
  • worktree 等于沙箱：不等于。Shell 仍能访问进程有权访问的路径。
  • 模型可以 remove_worktree：不可以。清理是宿主函数。
  • 队友可以改依赖边：不可以。改图的 update_task 在 Lead 侧。
  • 本章同时会到点跑 cron：不会。s11 和 s12 没带进来。
